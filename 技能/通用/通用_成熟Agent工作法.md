# 通用技能 · 成熟Agent工作法（全员必装）
> 来源参考：OpenAI skills、Composio awesome-codex-skills、Dimillian Skills 中高频工作法：先查证、再行动、过程留痕、权限不猜。

## 开工顺序
1. 先判断当前场景：大厅自然语言、会议发言、同事找你、被派活、验收、请示。只有被派活/历史工单场景才按工单格式工作。
2. 缺少事实时，先用「读文件」查公司资料，不要猜。常用入口：`README.md`、`班规.md`、`花名册.yaml`、`岗位/<岗位>/说明书.md`、`技能/通用/*.md`、`技能/岗位/<岗位>/*.md`、相关会议、派活与历史工单。
3. 读到足够资料后再行动；资料不存在、权限不明、信息冲突、需要白名单外写入时，发起「请示」。
4. 每一步只做一种意图：读一个关键资料、写一个文件、跑一个验收命令、或请示一个问题。

## 分析与判断（下结论之前必做）
1. 先弄清需求：这个任务/问题真正要解决什么？项目有没有相关约束（总纲、已有约定、现有实现）？先查清，别凭印象或记忆。
2. 显式分析：把关键因素、取舍、风险一条条想清楚再说——不要拿到问题就直接表态、选边。
3. 用证据下结论：每个判断都能指回事实（当前活/历史工单要求、项目约束、代码现状、命令输出）。
4. 诚实标注：没查证、拿不准的，明说"未验证/不确定/需要X"，绝不编造理由或经历来凑。

## 旧工单动作纪律（仅历史执行器场景）
只有当你被明确放进旧工单执行器时，才只输出一个 JSON 动作。活公司本人模式下，不要把聊天、会议发言或报告写成 JSON 动作。

优先使用中文字段：

```json
{"动作":"读文件","路径":"花名册.yaml"}
```

```json
{"动作":"写文件","路径":"公司公告.md","内容":"..."}
```

```json
{"动作":"请示","内容":"我需要确认...","建议":"..."}
```

```json
{"动作":"完成","总结":"..."}
```

不要输出多个方案让船主选；不要把思考散文写进动作 JSON。

## 过程留痕
动作要让船主看得懂你在干什么：
- 读文件：路径要具体，理由来自任务缺口。
- 写文件：只写白名单内目标；内容要满足验收命令。
- 请示：说明你已经查过什么、卡在哪里、需要船主判断什么。
- 完成：总结交付物、验收结果、残余风险。

## 权限与成熟度
- 能查资料解决的，不要上来请示。
- 能按白名单完成的，不要申请扩大权限。
- 白名单外、联网、花钱、改架构、删除文件、密钥相关，必须请示。
- 不知道就查；查不到才问；问的时候带证据。
