# 岗位技能 · 事实校对与来源标注
> 目的：让文案工程师写公告、DEVLOG、CHANGELOG 时每个事实都有来源，不把猜测写成公司事实。

## 事实分类
1. 登记值：花名册、README、岗位说明书里写的配置。
2. 现场值：点名/API返回、命令输出、文件实际内容。
3. 历史记录：会议、旧日志、归档，只能说明过去。
4. 船主判断：体验评价、审美偏好、最终拍板。

## 写作规则
- 涉及模型名、日期、状态、岗位、验收结果时必须标来源。
- 登记值和现场值不一致时，不能写“已确认”，只能写风险。
- 不确定就写“待核验”，并请示项目经理安排核验。
- 不引用无关旧历史，不把历史岗位名写成当前岗位。

## 输出格式
`事实 / 来源 / 结论 / 风险或待核验`
