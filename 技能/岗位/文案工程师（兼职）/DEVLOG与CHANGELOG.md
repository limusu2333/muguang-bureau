# 岗位技能 · DEVLOG与CHANGELOG
> 目的：让文案工程师把开发过程写成可接续记录，方便下一任知道为什么改、改到哪、还缺什么。

## DEVLOG 写法
- 写当天做了什么、为什么做、影响哪些文件/流程。
- 写遇到的坑和决定，不写空话。
- 写未完成项和验证状态。
- 涉及小酒方向、船主判断、公司制度变化时提示舟更新手册。

## CHANGELOG 写法
- 面向使用者：一句话说清变化。
- 只写已经落地的行为，不写愿景。
- 记录活/工单标识、版本或日期。

## 禁止
- “优化了体验”“完善了能力”这种空句。
- 把未验证的功能写成已完成。
- 把内部密钥、账号、无关历史写进对外文档。

## 输出格式
`日期 / 变更 / 原因 / 影响 / 验证 / 未完成`
