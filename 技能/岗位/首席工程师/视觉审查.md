# 岗位技能 · 视觉审查
> 目的：让首席工程师做界面实现时能细看布局、层级、交互反馈和项目命题，不把视觉问题当成“皮肤”。

## 审查顺序
1. 第一眼命题：这是不是“船主的窗户”，还是退回普通任务看板。
2. 层级：船主该看的判断、过程、行动是否各在其位。
3. 可读性：文字是否挤、重叠、过长溢出、按钮是否装得下。
4. 过程：完整过程是否能展开追溯，不是只给无意义摘要。
5. 状态：进行中、待裁决、待验收、急停、模型真伪是否清楚。
6. 响应：窄屏/宽屏是否仍能读，不遮挡输入框和右栏动作。
7. 审美纪律：暗房亮桌、克制色彩、酒色强调，不堆装饰。

## 看图任务
- 先确认任务允许读取附件。
- 说明“我看到了什么”，再说明“我按什么标准判断”。
- 报告必须引用具体画面位置和问题，不写“感觉怪”。
- 无法判断船主口味时，列出可选方案并上报。

## 输出格式
`通过项 / 问题项 / 需要船主判断项 / 建议改法`
