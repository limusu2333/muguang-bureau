记忆系统 · 调研落地 · 施工图 V1

五道闸门，
一套底盘。

五个问题不是五件孤立的活，是一条链：写入归一 → 主体归属 → 遗忘收口 → 统一删除 → 防固化自纠。它们共用同一批零件——所以先把底盘打好，五道闸各自只是接一段管子。下面每问一格：主流谁在用、我们抄谁（挑最轻最稳）、怎么落地、加多少成本。

底座SQLite 知识图谱 写前判定mem0 式 ADD/UPDATE/NOOP 人读层markdown 四区 检索向量 + FTS5 在场船主可亲核
先装底盘 · 五道闸都吃这四个零件

这四样一次装好，后面 5 个方案几乎零改造就能接。别一个问题一套机制——它们本来就是同一套东西的不同用法。

01 边表加两列

双时间轴失效

给边表加 valid_to / expired_at。事实被推翻不删、只关有效窗口。检索默认 WHERE valid_to IS NULL。抄 Zep/Graphiti。

02 稳定共享 ID

source_id 回指

每条事实一个 UUID，摘要挂 [src:uuid]、图谱边存 source_ids 数组、向量 payload 带 source_id。删除时 O(1) 找齐所有派生副本。

03 一次 LLM 判定

写前守门

新事实 + 语义相近旧事实一起喂 LLM，出 ADD/UPDATE/INVALIDATE/NOOP。归一、归属、矛盾闸全塞进这一次调用，不加次数。

04 船主在场

待亲核队列

低置信/高风险的不自动落盘，进队列等船主一键拍板。你档案核 ⚠️待亲核 那套，制度化进代码即可。

GATE 01–05五道闸 · 逐个落地
GATE 01

归一

entity resolution
已落地
病
老李/老板/李工/李先生……被当成好几个不同的人，关于你的记忆碎成几堆。
抄谁
Graphiti 的实体解析四步 + LINK-KG 的别名 cache（别名写入时学出来、不手填）。
怎么落地
一张别名表 seed（老板/主人→当前用户）+ 熵门控的模糊匹配（名字够长够独特才敢合并），绝不把两个真不同的人合成一个。
成本
几乎零——抽取那次调用顺带判。
GATE 02

主体归属

attribution
已落地
病
把老板的居住地/职业，错挂到某个员工头上。
抄谁
Graphiti 四条硬规则（说话人优先/代词消解到人名/占有者限定/两个明确节点）+ mem0 attributed_to；必须补 Graphiti #1171。
怎么落地
纯 prompt + 写前判定按同一主体圈候选、绝不跨主体比——防错挂的关键闸门。
成本
零成本，纯提示词。
GATE 03

遗忘 · 收口

forgetting
已落地
病
只增不减、越攒越肿，噪音把真东西淹了（mem0 本身没有遗忘）。
抄谁
Ebbinghaus 艾宾浩斯衰减（MemoryBank/SSGM）：随时间衰减、随命中回血的强度分。
怎么落地
久未命中的推断边随时间淡出活跃层；你亲口说的、钉住的永不淡。原话/历史仍在。
成本
离线批量、可缓，胖了再跑。
GATE 04

统一删除

unified delete
已落地
病
删一处、别处还留着，残影自相矛盾（mem0 真实 bug #3245：删了向量库、忘删图谱）。
抄谁
单一真相源 + 稳定 ID 回指 + 可靠传播（outbox 单事务 + 级联 + 黑名单防再长回来）。
怎么落地
跨层统一删——删"关于你"一条，图谱 + 船主档案同一件事一起清；原始流水按 ground truth 留着当撤销底。
成本
低，一次事务级联。
GATE 05

防固化 · 自纠

anti-ossify
已落地
病
一条错记忆/错教导反复蒸馏，滚雪球固化成"性格"（"微辣→辣→无辣不欢"）。
抄谁
Zep 双时态（矛盾才失效）+ SSGM 写前矛盾闸 + 流水对账（原则必须有原始流水撑着）+ 生成式agent 增量式（老原则原样留、不整段重写）。
怎么落地
蒸原则前过两道闸：流水对账（没据不升）+ 矛盾闸（碰根本底线不升）；巩固改增量式，只加不重写、矛盾才删。
成本
蒸馏那次调用顺带判。
阶梯

施工优先级（当初的排法）

先做GATE 02 归属四条硬规则 · GATE 03/04 失效非删除 + source_id（3/4/5 的地基，零成本）
接着做GATE 04 统一删除 + 向量防残影（私密数据，删不干净是硬伤）· GATE 01 归一
最后做GATE 05 遗忘衰减 + 防固化对账（长期健康，数据没爆不急）——但受保护白名单接口现在就留位
红线

唯一硬红线

她的宪法、她的边界，是受保护核心（M_core 白名单），蒸馏/对账永远不许覆写。五道闸再自动，这条只由人手动改——"防错误固化"最后、也最重的一道保险。
