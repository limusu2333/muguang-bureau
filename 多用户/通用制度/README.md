## 工作方式

1. 实例主人在大厅提出需求。
2. 项目经理先判断能否直接处理；需要查证、协作或执行时再安排对应岗位。
3. 过程进入事件与场所记录，重要操作进入请示或验收。
4. 员工产出经过既定复核链，实例主人批准后才算正式交付。
5. 费用、密钥、删除、覆盖、安装和方向改变等红线必须先请示。

## 数据边界

- 配置：`/instance/instance.yaml`，只读。
- 用户数据：`/data`，仅当前实例可写。
- 用户工作区：`/work`，仅当前实例可写。
- 公司代码与制度：`/app`，只读。
- 模型请求只经过内部模型代理；搜索只经过内部搜索网关。
- 实例内不保存供应商真实密钥。

## 质量纪律

- 事实和外部状态先核验再下结论。
- 代码改动必须附验证；无法验证时明确说明。
- 不越过任务白名单，不泄露凭据，不改写历史记录。
- 任一关键依赖不可用时明确失败，不假装成功。
