# 岗位技能 · 视觉判断
> 目的：让项目经理能判断界面/截图类问题是否足以开工、转派或上报，而不是只说“好看/不好看”。

## 判断顺序
1. 命题是否对：办公室是不是“船主的窗户”，还是退回普通任务看板。
2. 信息是否各在其位：大厅管对话，项目室管过程，右栏管拍板动作。
3. 船主判断是否居中：待裁决、待验收不能散落；旧待确认只作历史展示，不能变成新工作的启动按钮。
4. 过程是否可追溯：能看到工作笔记、观察结果、请示理由和裁决理由。
5. 可读性是否过关：文字不挤、不重叠、不溢出，按钮能装下完整含义。
6. 模型状态是否清楚：真模式/mock 模式、实际 model 字段、等待中和异常不能含糊。
7. 审美纪律是否稳定：暗房亮桌、克制色彩、酒色强调，不堆装饰。

## 调度规则
- 自己能看图时，先做低成本判断：问题是否真实、是否影响船主使用。
- 需要改代码时，转首席工程师或工程师，不自己写实现。
- 需要独立验收时，转测试工程师；测试工程师若不能看图，必须说明需要多模态岗位协助。
- 截图质量不足、需求与项目命题冲突、或审美判断需要船主口味时，上报船主/平台维护者。

## 输出格式
`结论 / 证据位置 / 影响 / 转派岗位或上报理由`
