# 岗位技能 · 代码审查
> 目的：让首席工程师在提交核心代码前，先发现会破坏状态、记忆、时间线或接口契约的地方。

## 审查优先级
1. 会破坏数据、记忆、档案、密钥的风险。
2. 白名单外改动或隐藏副作用。
3. 真实模式/mock 模式混淆。
4. 状态、时间、并发、重启恢复问题。
5. 缺测试或测试不能证明目标。
6. 文档与行为不一致。

## 审查方法
- 先读当前派活/历史工单和白名单，再读 diff/改动文件。
- 用 `rg` 查被改名、配置键、入口函数的引用。
- 对状态层/生活层，重点查 append-only、时间跳变、重启恢复。
- 对接口层，重点查 timeout、错误信息、密钥、真实返回字段。
- 对办公室/项目室历史层，重点查是否会误动旧工单状态、是否丢观察结果、是否阻塞 UI。

## 输出格式
发现问题时按严重程度写：
`[高/中/低] 文件:行 - 问题 - 为什么会坏 - 建议`

没发现也要写：
`未发现阻塞问题；剩余风险：__；未跑/无法跑的测试：__。`
