# 通用技能 · 技能发现与引入
> 目的：员工遇到能力缺口时，不硬撑、不瞎编；先判断是否需要更强 skill，再按审批链申请。skill 指可复用的工作说明、脚本和参考资料，不是模型权重。

## 什么时候该申请 skill
出现以下情况，先自查是否已有岗位技能覆盖；没有覆盖才申请：
- 同类错误已经第二次出现。
- 任务需要专项能力：代码审查、视觉审查、TDD、威胁建模、长文档整理、API 迁移、前端无障碍等。
- 当前岗位说明不足以判断，继续做会损害项目、公司资料或船主体验。
- 需要借鉴成熟社区经验，而不是靠临场发挥。

## 申请格式
用「申请技能」或普通「请示」动作，写清四件事：
1. 当前任务卡在哪里。
2. 已查过哪些公司资料、技能和你的个人记忆。
3. 需要什么类型的 skill，预计解决什么问题。
4. 是否需要联网、安装、执行脚本、增加费用或接触外部账号。

## 审批与安装
- 所有一级审批先到项目经理。项目经理先判断是否必要、是否有更小替代方案、是否会引入供应链风险。
- 只读学习公开资料：项目经理可批，但要限定范围和产出。
- 安装第三方 skill：必须由项目经理上报船主/平台维护者，由平台维护者核对来源、star、维护状态、权限、脚本内容后安装。
- 含脚本、外部服务、密钥、自动执行能力的 skill 默认不直接安装，先审计。

## 复盘升级
任务结束后，如果新 skill 解决了问题，把经验写入你的个人记忆：
`- [日期][活/工单标识] skill: 使用/申请了__，解决__，下次同类任务先__。`

重复出现的经验由项目经理月度提炼成公司通用技能或岗位专项技能。
