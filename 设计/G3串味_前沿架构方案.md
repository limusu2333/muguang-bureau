## 一句话结论（先给船主看）

**船主直觉对，第一轮偏旧偏"拼prompt"这一档。真正的病根有学名：我们把"最近30句"整段无差别灌进消息数组，等于没有"话题段"这个中间结构——旧话题的余温和新招呼被绑成同一段喂进去，模型顺着最近最显著的话题（B站）接话。**

架构级正解不是"提醒模型别翻旧账"，是**在拼上下文之前先判"这句是新招呼还是接旧话题"，判完再决定喂哪些历史**——脏上下文压根不进当前工作区，而不是进去了再叫模型忽略。

**而且这套我们几乎是量身的**：`记忆向量.py` 里已经有 embedding + 余弦 + 缓存，做"在线话题漂移检测"用的正是这三样，**不加新依赖、不训练、今晚能动手**。

## ① 有没有比"末位引导 turn"更架构级、更根本的方案？根本在哪？

**有。五路调研 95% 收敛到同一个词：会话切分 / 话题边界判断（dialogue topic segmentation / session boundary detection），并把它当成一等系统设计决策，而非后处理提示。**

### 根本区别：输出端求自律 vs 输入端做减法

| | 末位引导 turn（第一轮 / Character.AI Prompt Poet） | 话题边界 + 动态组装（这一轮） |
|---|---|---|
| 动作发生在 | **内容已全灌进去之后**，尾巴贴一句"别翻旧账" | **内容还没拼**的时候，先判"你在吗"是不是新话题 |
| 靠什么生效 | 模型的**注意力自律**——它能不能忍住不看 B站 | **结构切断**——B站那几句根本不进上下文 |
| 天花板 | "提示词写得多好"（软、概率性、每次赌模型状态） | "边界检测器准不准"（可测量、可回测、可调阈值） |
| 能 debug 吗 | 不能——为什么这次又串了？说不清 | 能——每次边界判定可打点、可回放、可复盘 |
| 物理约束 | **压不住**——基准证实：即便给了"别带入"的明确信号，模型仍 carry stale context | 旧内容没喂进去，无从带入 |

### 根本在哪（三条 2025-2026 硬证据，都是"边界是架构决策"的背书）

1. **"边界放哪里，直接决定 summarization / context selection / context reintegration"** —— *When F1 Fails / Episodic*（arXiv 2512.17083, 2025）。这是给船主"该在架构上不串"最直接的学术背书：边界是一等系统设计决策，不是后处理提示。

2. **无关历史留在上下文里，会实打实拉低当前 turn 准确率（task-switch interference），且模型有"位置偏置"——离得近的历史被过度当相关。** —— *LLM Task Interference*（arXiv 2402.18216, 2024）+ *Beyond Continuity*（arXiv 2605.09268, ICLR2026 workshop）。**这就是"你在吗"被最近的 B站染色的物理机制**，光靠提醒治不了。

3. **2025-2026 的 LLM 记忆系统已经把"话题 boxing"做成在线结构层**：*Membox / Topic Loom*（arXiv 2601.03785, 2026）在每个 turn 到达、看不到未来时就把同话题的 turns 归一个 box；它明确批评"把历史切成孤立 chunk、检索只按语义相似"——**就是我们现在 30句一刀切的病**。检索 F1 从 40.95 提到 53.95（LoCoMo）。

### 当下板块的坐标（证明方向够新）

*Recent Trends in Linear Text Segmentation: A Survey*（arXiv 2411.16613, 2024）把谱系理清：count-based(TextTiling) → embedding-based → supervised神经 → LLM-based，并明确点出**"全局方法不适用实时 chatbot，流式对话首选 TextTiling 范式 + 现代 embedding"**。第一轮扒的 mem0/Letta/Character.AI Prompt Poet 是"拼prompt"那一档（2023-24 味重）；这一轮的板块叫 **context engineering / dialogue topic segmentation / intent rewriting**，是 2025-2026 的当下。

## ② 落到我们真多轮 + FTS 架构，最该抄的架构级做法是什么、怎么改？

**最该抄的一件事：在"灌历史"之前，插一个「在线话题边界检测 + 意图路由」节点，把"一刀切最近30句"换成"当前话题段 + 按需 FTS 召回"。** 动的是"上下文怎么拼"这一层，不碰消息数组格式、不碰模型、不训练。

三路调研各给了一块拼图，拼起来正好落到我们底盘：

### 拼图 A（在线主路·成熟可直接抄）：per-turn embedding 余弦漂移检测

- **做法**：维护一个"当前话题段"。新消息进来，用 `记忆向量.py` 的 embedding 算它与**当前段质心（或上一条消息）**的余弦；低于阈值 τ 就判"话题切换"→ 当前段封存、开新段。
- **"你在吗"** 与"B站数据"段质心余弦极低 → 被判成新段边界 → 新上下文里根本不含 B站那几句。**串味从源头消失，是结构切断不是提示压制。**
- **学术锚**：TIAGE topic-shift 基准（arXiv 2109.04562, 2021）的经典判定就是余弦阈值 ≈0.25，2025 仍在用；工程实现可参考 `github.com/saeedabc/llm-text-tiling`（embedding 版 TextTiling 现成代码）。
- **为什么是它当主路**：这是唯一**天然在线、每 turn 即判、不需要看未来上下文**的一档。其余（CobSeg / TreeSeg / Def-DTS）都更准但离线，只能当归档纠偏，不能当在线主路。

### 拼图 B（一步两用·最能直接落到 FTS）：query 去上下文化 + 检索门控

- **做法**：每个新 turn 先跑一步"去上下文化"，判断这句到底依不依赖前文：
  - **招呼/新话题（"你在吗"）** → 它本身自足，不改写、**不去 FTS 翻旧账**；
  - **follow-up（"那 B站数据呢"）** → 改写成自足 query（补上"B站数据"）再喂 FTS / 组装历史。
- **一步同时**判了新旧、又把 FTS 检索给门控了——招呼句根本不触发全量检索，顺带省算力。
- **出处**：*Decontextualizing User Questions for open-retrieval ConvQA*（arXiv 2507.04884, 2025）；*Learning When to Retrieve / What to Rewrite*（arXiv 2409.15515, 2024）。这是把"何时检索、是否改写"做成显式决策节点，正是我们 FTS 缺的门控。

### 拼图 C（招呼词兜底·极贴我们）：handshake / 招呼线索识别

- *DASH*（arXiv 2512.15042, 2025）专门识别"开启新话题的交互线索"——"在吗""我问个别的""对了"这类招呼。思路对我们"你在吗=新招呼"极贴。**它本身是离线 LLM，别抄成在线实现，只抄这一条思路：把高频招呼词做成规则强边界信号。**
- 规则 + 模型双保险：`你在吗/在/在吗/忙不忙/在干嘛/吃了吗` 这类高频招呼**直接命中规则判新段**，不进模型、不触发 FTS；模糊的才交给余弦漂移。

### 落到我们底盘的干净映射

| 生产记忆系统的三层（Zep/Letta/Mem0 共识） | 我们已有的资产 | 该怎么用 |
|---|---|---|
| working（当前会话状态） | 当前多轮数组 | **只放当前话题段**，不再是拍平的30句 |
| episodic（过往具体交互） | 每日摘要 + 大厅历史 | 旧段封存进去，**命中才召回** |
| semantic（长期事实/人格） | 个人四区记忆文件（system 里） | 恒定常驻，已对 |

**我们缺的从来不是记忆检索，是"段"这个中间结构。** 补上"段"，FTS 就从"背景无脑全量灌"变成"按话题命中召回"。

### 具体改三步（可只上第一步先看效果，旁路验证）

**第一步（核心·止血·今晚能上）——在 `构造聊天消息`（:385 `records[-30:]` 那圈循环之前）加"当前段"判定：**
1. 招呼词规则先兜底：最新句命中招呼词典 → 判"新段"。
2. 否则调 `记忆向量.py` embedding，算最新句 vs 最近段质心余弦 < τ → 判"新段"。
3. **判"新段"时**：`records[-30:]` 不再整段进，只保留最近 1~2 轮 + 人格/摘要（system 已有），旧话题不进数组。
4. **判"续段"时**：维持现状（近端逐字），follow-up 手感不动。

**第二步（治本·门控 FTS）——把 `聊天唤醒`（:415）里"问过去先查 FTS"改成门控：**
- 新段/招呼句 → 不主动触发 FTS。
- 续段/明确回溯（"接着刚才 B站说"）→ 用去上下文化后的自足 query 去 `search_hall_history`/`semantic_search`，只召回命中段。

**第三步（可后置·离线纠偏）——每日摘要/归档时，用离线更准的分段（CobSeg/TreeSeg 思路）给历史重新划段**，喂回 episodic 供检索。非在线主路，改动面大，留下一轮。

### 关键参数与坑（船主要知道）

- **阈值 τ 别硬抄 0.25**——那是 TIAGE 英文基准值。中文 + 我们同事带名的多方对话分布不同，得**在真实大厅对话上标十几条边界回测**再定。
- **加迟滞/双条件防误切**：连续两条都低于 τ 才切段，或叠加招呼词强信号，避免一句短消息误判成话题切换。
- **同事带名的 user 消息**（老纪、老梁…）在质心里**降权或按发言人分流**，防止多人插话被误判成话题切换。这一点第一轮那份"说话人前缀根因修复"已经踩过一次相关的坑，同源。
- **旁路先跑**：老路径照跑，新检测器**只在日志里标边界**，比对几天觉得准了再切主路。

## ③ 诚实评估：真有更高级的，还是"末位引导 turn"其实已是务实最优？

**诚实说：确有更高级、且这一次不是花架子——因为我们手里正好有 embedding+余弦+缓存这套零件，在线话题分段对我们是"低成本真落地"，不是"研究阶段太重"。** 但要分清哪些能抄、哪些是花架子别碰。

### 真能落、值得抄（务实）
- ✅ **per-turn 余弦漂移 + 招呼词规则**（在线主路）：我们 `记忆向量.py` 已有全部零件，工程量小、天然在线、可回测。**这是这一轮真正的升级，不是花架子。**
- ✅ **query 去上下文化 + FTS 门控**：ConvQA 里非常成熟的标准管线，我们 FTS 直接受益，风险低。
- ✅ **working/episodic/semantic 三层 + 检索期不调 LLM**：Zep/Letta/Mem0 生产验证，我们四区文件+摘要+多轮数组正好对应，架构模式照搬。

### 是花架子 / 太重 / 研究阶段，这轮别碰（不为显高级而推荐）
- ❌ **注意力层 steering / KV 操纵**（PASTA/SpotLight/ContextFocus，When Attention Closes）：效果最"根本"（直接掰注意力），但**要能改推理层 logits/attention，我们走 API 够不着**。列它只为标天花板在哪，不建议碰。
- ❌ **temporal knowledge graph**（Zep/Graphiti 图谱那套）：对我们单人陪伴场景**偏重**，semantic 区用文件+FTS 已够，图谱暂缓。
- ❌ **Def-DTS / DASH 的 LLM 原生演绎分段当在线主路**：准度高但 whole-dialogue + 多次 LLM 调用，**贵且离线**，只抄"招呼即新话题"这一思路，别抄成在线实现。
- ❌ **Membox 的 Trace Weaver 跨 session macro-topic 连线**：2026 新论文，思路可借、代码未必现成，作为 v2 观望。
- ⚠️ **RECAP 式意图重写**（arXiv 2509.04472）：概念级正解（把历史压成"用户最近意图的干净陈述"再喂），但它多一次 LLM 调用、且**实例主人边界感强，重写可能把他真想续的旧话题误杀**。可作第二步的一个变体，但比"余弦分段"重、更容易伤 follow-up 手感，**不作首选**。

### 关于"末位引导 turn"到底还留不留
**不是全废，降级成兜底。** 余弦分段是"该不该喂由架构先决定"（硬、确定），末位引导是"喂进去了再叫它别看"（软、概率）。**主力换成分段；末位引导可保留一份当最后一道软兜底，但不当主力。** 第一轮把它当主力，是board 打回的正确理由。

### 一句诚实的话
如果我们**没有** embedding 那套零件，我会老实说"在线分段要现搭 embedding 管子、性价比存疑，末位引导先顶着"。但我们**有** `text-embedding-v4` + `_余弦` + 磁盘缓存现成——所以这一轮的"更高级"是真能落的低成本升级，不是研究论文里的空中楼阁。船主的直觉这次踩在了一个我们恰好够得着的更高台阶上。

## ④ 给船主的明确推荐 + 需要你拍板的点

### 明确推荐
**主路换成"在线话题分段"，分三步落，先上第一步旁路验证。**

1. **第一步（必做·止血）**：`构造聊天消息` 加"当前段"判定 = 招呼词规则兜底 + embedding 余弦漂移。判新段就不把旧30句整段灌进去。复用 `记忆向量.py`，不加依赖。
2. **第二步（治本）**：`聊天唤醒` 里 FTS 从"默认查"改成"门控查"——招呼句不触发，续段才用自足 query 召回命中段。
3. **末位引导 turn 降级为软兜底**，不当主力。
4. 离线重划历史（第三步）留下一轮。

**性价比排序**：第一步 >> 第二步 > 末位兜底 >> 其余全部（图谱/steering/RECAP 这轮都不做）。

### 需要你拍板 / 亲核的点
1. **阈值 τ 要你陪着在真实大厅对话上标十几条边界回测**——中文+同事带名的分布，不能硬抄英文基准 0.25。这是唯一需要你的真实数据的地方。
2. **招呼词典由你定**：`你在吗/在/在吗/忙不忙/在干嘛/吃了吗/在不在`……这几个直接判新段、不进模型。你补几个你常用的。
3. **"新段"要收多狠**：判新段时旧话题**整段清出**，还是留最近 1~2 轮当缓冲？我建议留 1~2 轮防误切伤 follow-up，你定。
4. **先旁路观察几天再切主路，还是直接切？** 我强烈建议先旁路（只在日志标边界、老路照跑），比对准了再切——避免误切把你真想续的话题掐了。
5. **验收口径**：`你在吗/在忙吗/吃了吗` 三句贴在一段旧 B站话题后跑，看还会不会被答成旧话题续写；再拿"那个再核下/接着刚才 B站说"验 follow-up 还接不接得住。**两组都过才算治好。**
