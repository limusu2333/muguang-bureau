# 公司自动备份闭环

日期：2026-08-16

## 为什么之前会出问题

旧公司留下的 `com.xj.backup` 只备份 `20_工程_XJ`。开发公司虽然已经有能生成、校验和恢复快照的程序，但迁移时没有把“谁定时调用它”一起迁过来。因此系统能发现备份变旧，却没有任何定时任务负责产生新备份。

这不是备份文件本身损坏，而是备份程序和 macOS 定时任务之间缺了一段连接。此前测试只验证“手动运行能生成 ZIP”，没有验证“重启后仍会自动运行”，所以遗漏没有被拦住。

## 现在如何运行

1. macOS 每天 04:30 唤醒一次当前开发公司的备份任务，登录或重新加载任务时也会唤醒。
2. 唤醒不等于每天生成备份。程序每 3 天才比较一次公司文件；没有变化只记录检查结果，有变化才新建 ZIP。
3. 新备份必须通过 ZIP、文件清单、逐文件哈希和 SQLite 完整性校验，失败不会覆盖或删除旧备份。
4. 每月把最新备份恢复到临时目录，在副本中运行全套检查。真实公司不会被覆盖。
5. 重要操作可以直接选择“重新备份并核验”，该动作调用备份程序，不经过项目经理或模型。
6. 超过 4 天没有完成检查时提醒，超过 7 天时严重告警。告警写明是定时任务未接入、备份损坏、维护失败、检查超期还是恢复演练失败。

## 异盘副本

系统已经支持每 7 天把最新备份复制到另一块磁盘并再次校验，但不会擅自选择磁盘。`备份策略.json` 的 `异盘目录` 目前为空；先生确认目标目录后填入才会启用。

## 防止以后再次遗漏

- `工具/备份任务.py --check` 同时检查配置文件、执行路径和 macOS 是否已经加载任务。
- 回归测试钉住定时任务必须指向当前 `30_开发公司`，不能再指向旧公司。
- `/健康` 同时检查自动任务、最近检查、最近成功、最新备份能否打开、最近恢复演练和异盘状态。
- 健康页只做快速可读性检查，避免频繁全量读取大备份；完整校验由备份任务在真正需要时执行。

## 2026-08-16 现场结果

- 当前公司定时任务已安装并被 macOS 加载。
- 第一次恢复演练发现 macOS 定时任务环境里缺少 Homebrew 工具路径；已补齐固定路径后重新运行。
- 第二次恢复演练退出码为 0，恢复 1207 个文件并通过全套检查。
- 异盘目录尚未指定，因此状态明确显示“未配置”，不会伪装成已经完成异盘保护。
