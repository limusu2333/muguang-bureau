# 记忆系统 · 全图（从简到繁，一页拿住）

> 给船主和下一个舟/codex 的记忆系统总览。从最简的两大块，到每个抽屉、一天的循环、和底下的核心技术——全用人话讲透。看完这一页，这套系统是你的，不是架空你的黑箱。
> 对应可视版 artifact；本 md 是仓库内版本控制的权威副本。架构正文沿用 2026-07-14 的设计基线；2026-08-26 现役开发版使用 `qwen3.7-text-embedding` + 本机 `mlx-community/Qwen3-Reranker-4B-mxfp8`，云端 `qwen3-rerank` 欠费只保留为历史故障。正式封存的暮光 v1 不改。

## 00 · 它到底干嘛的
一个每聊完就忘光的员工，没法用。记忆系统就是**公司怎么记住事**——记得**发生过什么**、记得**学到的规矩**、记得**你是谁**。三件事，一件都不能断。

## 01 · 最简：记忆就分两大块
- **每个员工自己的记忆**：老钟/老梁/阿强/老纪/阿言，五个人各有一本册子。记他自己干过的活、学到的规矩、你给他立的规矩。记忆跟着人走。
- **关于「示例主人这个人」的记忆**：全公司共享一份。专门记你——你是谁、住哪、用什么机器、最近什么状态、心情往上还是往下。让每个员工都认得你。

> **现在存在哪（2026-07-09 搬迁，实体化办公）**：**个人记忆跟人进部门**——存在他部门的目录里（`编程部/老梁.md`、`编程部/阿强.md`、`编辑部/阿言.md`、`经理办公室/老钟.md`、`测试部/老纪.md`；按人名一个文件、调岗册子跟着搬，＝"记忆跟人走"落到磁盘）。**公共记忆（关于你的）进资料室**——`资料室/船主.md` ＋ `资料室/图谱.db` ＋ `资料室/会话摘要.md`，全公司共享一份、谁都来查。原来混放两者的 `记忆库/` 现在只剩杂项（抽取日志/巩固状态/待确认）。路由由 `工具/部门/__init__.个人记忆路径` + `工具/资料室.py` 定；为什么这么分见《权限与交付链_2026-07-09》。

## 02 · 员工的册子 · 四个抽屉
从"生的原料"到"熟的规矩"，一层比一层提炼。（代码：`活_本人.py` 的 `记忆区序 = (原则, 船主教导, 近况, 流水)`）

| 抽屉 | 是什么 | 性质 |
|---|---|---|
| **记事（流水）** | 每聊完一场，按原话记下发生的事，**只往上加、永不改动**。这是"地面真值"——摘要哪天理岔了，翻回这查得到当初到底说了啥。 | 只加不改 · 铁底 |
| **近况** | 一小段"他最近在忙啥、什么状态"，每次巩固时重写，永远只反映当下。 | 滚动摘要 |
| **原则** | 从流水和你的叮嘱里**蒸出来的"该怎么做事"的规矩**（如"先方案后动手"）。员工的"做事性格"。 | 攒出来的 |
| **叮嘱（船主教导）** | 你**亲口**给他立的规矩，原话不动，你随时能改删。最可信的一格。 | 你亲口立的 |

唤醒员工时先带原则、叮嘱、近况和近期流水；更早、更散或跨来源的内容按需走 `unified_search`。这避免把多年流水整本塞进上下文，也避免只看末尾几条而漏掉旧但关键的教训。

## 03 · 关于你的记忆 · 两份（硬 + 软）
- **图谱（硬 · 结构化）**：`图记忆.py` + `图谱.db`。把关于你的事实拆成 **"谁—什么—值"** 的三元组带日期（*示例主人—居住地—咸阳*、*示例主人—主力机身—A7M5*）。只认十种关系（职业/居住地/主力机身/用/拍/在意的人/说过要做/当前状态/偏好/有过；其中职业/居住地/主力机身/当前状态是"单值"=只能有一个现值）。最大本事是**会自我纠正**：换机身，旧值自动作废、留最新。
- **船主档案（软 · 有温度）**：`船主记忆.py` + `船主.md`。记图谱装不下的软东西，五格：基本事实/他在意的_偏好/近期状态流水/当前状态基调/他说过要做的事。
- 一个配角：**会话摘要**（`会话摘要.py`，每天自动记一行今天聊了啥），负责“最近整体发生了什么”，不是事实搜索结果。

## 03.5 · 怎么找：一扇门，四类证据

现役搜索入口只有 `unified_search`。它不是把四个旧工具的文本拼起来，而是统一做查询理解、时间/人物过滤、混合召回、重排、证据合并和失败报告：

1. **公司文档**：README、班规、岗位/技能和现役设计；历史设计会明确降权并标“须再验代码”。
2. **大厅原话**：逐条 JSONL 原始发言，带说话人、时间、文件和行号。
3. **本人私册**：只查当前调用者自己的部门册子；人物筛选参数不能把权限切到同事名下。
4. **公共图谱**：现行事实、有效时间、原话和真正多跳路径；统一搜索走严格只读口，不偷偷增加命中强度。

底层先用 `qwen3.7-text-embedding` 同时生成密集向量和稀疏关键词，再和中文字面匹配做多路召回；随后用本机 `mlx-community/Qwen3-Reranker-4B-mxfp8` 重排。低于证据门槛就返回“没找到”，不拿第一名硬凑。某个来源或模型接口故障时状态为“不完整”，还能显示其他可靠命中，但绝不能据此声称“全公司没有”。`recent_hall_chats` 仍保留，只负责按时间翻最近几天，不参与相关性搜索。旧 `text-embedding-v4` / 云端 `qwen3-rerank` 仅作为历史方案，不是当前依赖。

## 03.6 · 2026-08-26 资源边界

- 精排只取每篇候选最后位置的 `yes/no` 两个分数，不再生成整段文本乘十五万词表的巨大结果。真实首次推理峰值约 `4.22 GB`，此前约 `50 GB` 的异常峰值已消失。
- 4B 精排住在独立子进程里，办公室启动和健康检查都不加载它；第一次实际搜索才加载，空闲 180 秒后卸载。卡死超过 60 秒时只更换精排子进程，不要求重启整间公司。
- 硬上限是：16 篇候选、单篇 2048 个令牌、一次总计 24576 个令牌、批大小 2、每批补齐后最多 4096 个令牌、MLX 缓存 256 MB、活动内存超过 8 GB 时停止接新请求。
- 同一时刻只有一个推理工作者，外加三格等待队列。队列满、输入超限、等待超时或模型失败，都保留字面/稀疏等基础证据继续回答；一次坏搜索不能让普通聊天失败。
- 一次员工唤醒最多使用两次统一搜索。询问当前版本直接读版本账，询问谁在忙直接读在岗账，不增加模型调用。
- 2026-08-26 两个开发工作区已完成代码整合；整合后唯一候选源的隔离回归为 `151/151`，多用户单元测试为 `204/204`，完整 `make release-check` 通过。此前两边 20 个并发请求均为 4 个处理、16 个明确限流，峰值约 `4.18 GB`，仍作为已验证资源基线。这些是开发版事实，不代表候选已生成、宿主已迁移或版本已发布。

## 04 · 记忆怎么"活"：一天的循环
记忆不是死在硬盘上的表格，一天里走三步：
1. **白天·写 → 聊完就抽取**（`记忆抽取.py`）：每场对话收尾，自动把"该记的"抽出来分门别类塞进各层。
2. **整理·巩固 → 用时补账**（`记忆巩固.py`）：流水蒸原则、更新近况、给关于你的事实对账去矛盾、把冷掉的旧事实淡出。
3. **用时·喂 → 核心注入 + 按需搜索**（`活_本人.py` + `统一搜索.py` + `船主记忆.船主画像注入`）：先给身份、当前状态和核心记忆；需要旧事或跨来源证据时再精确检索。

> **"巩固"什么时候真跑？（重要，别被"睡前/每晚"这类说法误导）** 它**不是半夜定时器**，而是挂在对话后台线程里（现役入口 `机房.py` → 活厅收尾 → `记忆巩固.巩固到期的人`，docstring"每天第一场对话收尾后"）：**你每天第一次跟公司说话时顺手触发一次**（`.巩固状态.json` 记日期，每人每天最多一次）。所以在这台**非 24 小时开机**的个人机器上，**电脑关着、公司没开都不会漏**——下次用它时把隔的这些天一起补上。间歇使用也不丢：隔十天半月回来，`会话摘要.补齐摘要()` 会一次补齐所有落下的活跃日，原则/近况/图谱也都正常补上。代码里"睡前/每晚"是借 Letta sleep-time 概念的**比喻**，真实触发是"用时补账"。

## 05 · 核心技术点 · 人话点透（全抄被验证过的，非手搓）
| 技术 | 干嘛 | 治什么病 | 抄谁 |
|---|---|---|---|
| **写前判定** | 落新事实前先翻有没有类似的——有就改、重了就跳过、真新才加 | 重复灌、盲目覆盖 | mem0 |
| **失效非删除** | 事实变了不删旧的，只盖"从这天起不算数"的时间戳；历史可回放，问"现在"只给最新 | 换机身/搬家：旧值既不该消失也不该冒充现在 | Zep 双时态 |
| **归一·别名** | 老李/老板/李工全认成同一个"示例主人"，不碎成几个人 | 称呼一多，记忆散成几堆 | Graphiti |
| **混合召回 + 重排** | 中文字面、密集向量、稀疏关键词和图路径各自找候选，再由专用重排模型判断能不能直接作证 | 只搜关键词会漏同义改写；只搜向量会把“味道相近”当答案 | DashScope embedding/rerank + RRF |
| **证据门槛与拒答** | 低分结果不返回；每条带路径、行号、人物、时间和来源状态 | “总得给五条”导致编造式检索；坏一路却假装全查完 | LongMemEval 式可答性边界 |
| **归属·防张冠李戴** | 你的事记你头上、员工的活记员工头上，不互相安错 | 老板的居住地错挂到员工身上 | Graphiti #1171 |
| **防误固化** | 气话/随口话/错教导不会被当"原则"记一辈子——得流水有据、不碰根本底线才准升 | 取消待审门后错话直接进叮嘱又被蒸成性格（实测拦住"所有代码不用测试"） | SSGM / Graphiti |
| **巩固·增量式** | 巩固整理时：老规矩原样留不重写、只加新的、被流水显式反驳才删；涨过40才压缩一次 | 迭代摘要滚雪球漂移（"微辣→辣→无辣不欢"）、"最近没提到就误删" | Zep / 生成式agent / Letta |
| **遗忘·衰减** | 冷门没人用的"推断"事实随时间淡出；你亲口的、钉住的永不淡 | 只增不减、越攒越肿 | 艾宾浩斯 / MemoryBank / SSGM |
| **跨层统一删除** | "关于你"删一条，图谱+船主档案同一件事一起清 | 删一处别处还留着、自相矛盾 | mem0 #3245 教训 |
| **情感register** | 每轮先读你此刻情绪（平静/累/烦/低落/脆弱/高兴），难过时话放软先接住别甩进度；判定门挂了大声报错绝不编假"平静" | 你随口寒暄五人回你五份公文；你哀伤它跟你聊色板 | 陪伴型AI 情绪register |

## 06 · 这一程把它变成了啥
- 从：**只会往上堆 · 会漂移 · 把错的固化成性格 · 越攒越肿**
- 到：**会自我纠正 · 防固化 · 防漂移 · 有边界**
- 每步都抄被工业界/学术界验证过的（mem0 · Zep/Graphiti · SSGM · 生成式agent · Letta），不是闭门手搓。已收口的改动都有对应提交和验收；当前开发版仍可能有未提交施工，必须提交并按范围验收后才能进入候选。
