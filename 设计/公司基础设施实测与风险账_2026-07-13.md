## 4. 整改前风险排序（保留作追溯）

以下是本轮开工时的原始风险和验收线。代码层整改结果见 2.1 节与施工记录；这里保留原文，防止以后只见绿灯、不知道为什么要有这些护栏。

### P0：先保住数据和控制权

1. **执行室不是真沙箱**
   - 现状：允许解释器和构建工具执行任意代码，继承父进程环境；目录判断可前缀绕过；`find -delete` 可删除。
   - 后果：岗位一旦被提示注入、依赖脚本或错误命令带偏，可读取密钥、改删越界文件或执行供应链脚本。
   - 验收线：子进程使用显式最小环境；路径用 `Path.is_relative_to()`；危险参数和解释器能力另设隔离进程/容器；删除必须单独确认。

2. **任务没有耐重启能力**
   - 现状：守护线程承载真任务；日志已出现未收尾异步任务；9 个会话无结束标记。
   - 后果：重启或崩溃时，产出、记忆抽取、事件尾部和状态可能只完成一半。
   - 验收线：任务先持久化再执行；有明确的进行中/完成/失败状态；SIGTERM 优雅停机；重启后可恢复或明确标失败。

3. **两道交付门在内部异常时放行**
   - 现状：模型“审崩/判不清”已经安全拒绝，但代码内部异常仍 `return True`。
   - 后果：最需要门禁时，门禁自身故障反而放过交付。
   - 验收线：任何未明确得到合规放行结果的路径都不得进入下一层，并产生船主可见告警。

4. **回归套件会清真数据**
   - 现状：管理动作目录不在快照内，测试启动会删除所有待确认和已办卡；也没有阻止在服务运行时执行。
   - 后果：一次“跑全绿”可能抹掉真实管理记录，或覆盖测试期间的并发写入。
   - 验收线：测试必须强制指定临时公司根；默认检测到真根或 8787 运行就拒绝；快照覆盖所有会写数据；不能靠测试结束时补写回去。

5. **验收没有绑定被验内容**
   - 现状：记录只保存路径和描述；文件可在提交后变化；先写产物、后登记验收。
   - 后果：批准的未必是当时看到的版本；崩溃可留下无主产物。
   - 验收线：先建“进行中交付”；提交时保存 SHA-256、大小、提交时间和 Git 版本；批准时验证内容未变。

### P1：再补可靠性闭环

1. **管理动作缺少恰好一次保证**：应先落执行意图/幂等键，再执行，再原子落完成；重试必须识别已执行结果。
2. **事件总线静默失败**：落盘失败、坏 JSON、队列满都需要计数、告警和可恢复的游标/重放机制。
3. **健康检查混淆“端口活着”和“服务可用”**：429 是限流、500 是服务故障，不能显示健康；明文 HTTP 地址不得携带密钥探测。
4. **备份不覆盖源码连续性**：当前只备状态，同盘、保留 10 份；应增加源码/未跟踪关键模块清单、SQLite 在线备份、异盘副本和定期恢复演练。
5. **版本不可复现**：`requirements.txt` 未锁版本；大量核心模块未跟踪；`.gitignore` 未覆盖新运行数据，既可能丢代码，也可能误提交真实数据。

### P2：容量与外部输入

- 附件缺少字节上限和 MIME 类型校验，可导致内存/磁盘耗尽。
- 网络工具没有私网地址阻断、响应体上限和重定向后复核，存在 SSRF（服务端替攻击者访问内网）与大文件风险。
- 归档只覆盖少数 JSONL，未覆盖会话事件和向量缓存；当前二者已持续增长。
- `机房.py`、`活_本人.py`、`平台_工具集.py` 和前端大页面继续膨胀，改动的耦合范围正在扩大。

## 5. 文档勘误

以下旧说法不能再作为当前事实：

- “交付门/收敛门任何错误都不放行”只覆盖模型结果解析，不覆盖内部异常。
- “回归前后自动还原，绝不污染真公司数据”不成立，至少管理动作卡不在快照内。
- “执行室只允许测试/编译/只读检查”不成立；程序白名单不等于行为白名单。
- “待验收显示真实文件”只能证明路径，不证明验收时的文件版本。
- “健康绿灯”目前只说明收到某类 HTTP 响应，不等于鉴权、额度和服务都可用。
