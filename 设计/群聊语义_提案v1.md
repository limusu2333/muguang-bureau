# 群聊语义提案 v1（2026-07-03，只提案未施工——船主点头才动）

## 一、扒到的头部做法（抄件来源）

### SillyTavern 群聊（陪伴社区群聊的事实标准，超高星）
Natural Order 三步激活，一步中了就停：
1. **名字提及**：话里出现某人名字（完整词）→ 这个人必须被激活出来说话。
2. **健谈度（talkativeness）**：没被点到的人，按各自的健谈度百分比**掷骰子**决定冒不冒泡——0%=内向只应点名，100%=话痨每句都接，默认50%。
3. **随机兜底**：前两步一个都没中 → 随机拉一个出来，群里永远有人接话。

辅助机制：Mute（禁言某人）、Force Talk（手动点谁谁必须说，绕过一切规则）、Allow Self Responses（自己话里提自己名不触发，防自嗨循环）、Auto-mode（无人输入时自动接龙）。

### AutoGen SelectorGroupChat（微软，任务型群聊标准）
任务型对话不靠骰子——由**选择器**读上下文+各岗位描述，点名下一个发言人；默认不连选同一人。闲聊和干活是两套选人逻辑。

## 二、我们的病灶（2026-07-03 船主真机撞见的）
- **每句话五人全醒全思考**：贵、慢（"gpt先思考了半天"），也不像真人——没人整天竖着耳朵逐字分析每句闲聊。
- **点名语义乱**：问"测试工程师是谁"，PM抢答、老纪反而没出来。
- **场所常识缺口**：老纪把"在大厅说话"误会成要写文件，跑去请示写权限（tests/** 白名单）——说话根本不经文件。

## 三、提案：唤醒前路由（三层规则架构不动，只改场所的"谁被叫醒"）

1. **点名优先**（抄ST第一步）：话里完整出现某人名字/岗位 → **只唤醒被点的人**（可多个）。@语法保留=Force Talk。
2. **健谈度掷骰**（抄ST第二步）：没点名的闲聊，按花名册新增的`健谈度`字段掷骰子决定谁醒。骰子本身就是"偶尔皮一下"——低健谈度的人偶尔中签插一句，恰好是真人感。冒泡上限2~3人防刷屏。
3. **任务话必醒制片**（抄AutoGen思路+他职责牌现有的"任务必接"）：像任务/需求/安排的话，老钟必在唤醒名单里。
4. **随机兜底**（抄ST第三步）：一个没中 → 唤醒老钟（他职责牌本有冷场兜底）。
5. **只有被唤醒的人才思考**：省钱省时，其他人这轮就是"没看手机"。
6. **场所常识补丁**（规则牌加一句，治老纪的误会）："在大厅说话＝把话直接说出来，你的发言本身就是回复，不需要写任何文件、不需要任何权限。"

## 四、要船主拍的（商量点）
1. 健谈度各给多少？建议初值：老钟80 / 阿言60 / 老梁40 / 阿强40 / 老纪25（他本来就闷）。要不要做进班子页当滑杆可调？
2. 闲聊冒泡上限：2人还是3人？
3. "任务话"的判定：先用便宜的规则（祈使词/需求词/@），不准再升级成小模型路由（每句一次轻调用）？
4. 点名的人被唤醒后，别人完全不知情（真人感强、最省），还是老钟仍然旁听（组织上稳）？
