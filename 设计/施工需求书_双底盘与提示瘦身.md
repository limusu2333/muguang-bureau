# 施工需求书：双底盘改造 + 提示瘦身 + 称呼改制（2026-07-03 实例主人拍板）

> **历史施工需求，不是现行架构说明。** 其中旧入口、旧目录和限制仅用于追溯当时施工；当前事实以根 `README.md`、现役代码和最新实测为准。

施工方：Codex。验收方：舟。
**哲学（本单的魂）**：模型很强，降智是我们造成的——聊天被跑在办事底盘上、规章每次唤醒全文灌顶。
改成：**推给人的只有身份和记忆，其余一切他自己有脑子去查**。平台硬约束（权限白名单/验收闸）在代码层，不靠背条款。

红线同前单：零新依赖；只学机制不抄GPL代码；不碰 前端/、.git、记忆库/ 真实文件；自测隔离；中文命名。
先读懂：工具/活_本人.py、工具/办公室.py 群聊段、工具/大厅记录.py、agentscope 的 Msg/Agent/memory/ChatModel 相关 API（.venv 里翻源码确认，不许猜）。

## 工单一：称呼改制（全局）
1. 所有**模型看得见**的提示文案里，"船主"改为"实例主人"：办公室.py 的"## 船主现在说"、耳朵行、冷场铃；常识门.py 的原因字符串（"船主像是接着你刚才的话"等）；大厅/规则牌.md 行文。
2. 每个唤醒的系统提示加一行：称呼规矩——对老板当面一律称"实例主人"。
3. **内部身份标签一律不动**：大厅记录 who=="船主"、常识门/办公室里的 `== "船主"` 判断、前端 isOwner——这些是数据兼容层，改了会断档案连续性。

## 工单二：聊天底盘（新）
办公室群聊路径（含只发言与制片в群聊里的发言）改走新函数 `活_本人.聊天唤醒(岗位, 本轮已说, 会话id...)`：
1. **真多轮消息**：从 大厅记录.读对话() 取最近 30 句构造消息数组——实例主人的话=user；**本人自己说过的话=assistant**；其他同事=user 且内容前缀 `[名字] `；本轮已说的同事发言同样按此追加为 turns。最新一句=最后一条 user。
2. **系统提示一页纸（≤600字）**：身份一句（你是X，公司Y岗）+ 性格一句（从花名册 abilities/routing 提炼或新加 `性格` 字段）+ 称呼规矩 + 记忆精华（教导+原则+近况，砍流水）+ 近期公司摘要 + 群聊礼仪三条（不想说只答[沉默]；前面同事说过的不重复；**被问过去的事必须先用工具查档案，查不到就说记不清，禁止凭印象编**）。
3. **工具只带两件**：search_hall_history / recent_hall_chats（复用现有）。
4. **技术路线**：先查 agentscope 能否给 Agent 预填多轮 memory（把历史 Msg 灌进 agent.memory 再 reply）；不行就直接用 建模型() 的 ChatModel 做多轮调用+原生 tool-calling 循环（聊天不需要 ReAct 全家桶）。选哪条路写进施工报告并给出依据（贴 API 源码行号）。
5. 事件流兼容：聊天唤醒也要能发"群聊发言"级别的事件回办公室（现有编排里由办公室发布，保持不变即可——聊天唤醒只需返回最终文本）。

## 工单三：干活底盘瘦身
唤醒本人（现有 ReAct 路径，供任务/会议/派活）系统提示改为：
1. 身份 + 称呼规矩 + 四区记忆注入（保持）+ 近期公司摘要（保持）。
2. **职责牌不再全文灌**：只注入说明书的「岗位定位」一段（第一个二级标题下的内容，≤200字），其余改为**指路牌**："你的完整说明书在 岗位/<岗>/说明书.md，班规在 班规.md，技能在 技能/——牵涉职责边界、流程、权限的活，动手前自己先读相关部分。"
3. 保留的硬提示只剩三条红线：要请示的事项（删除/花钱/密钥/最终交付）、别造假（查不到就说没查到）、产出要落到能验收的位置。其余"活人宣言"等长段删减合并。
4. 群规不再拼进每次来意（聊天底盘已内化为礼仪三条；办事场合不需要群规）。

## 自测与交付
- py_compile 全部。
- **"它"字回归测试**（关键验收）：复刻 2026-07-03 14:29 现场（大厅记录截至那一刻的12句 + "？人呢 老钟你去看看它干啥呢？"），走聊天底盘真调一次项目经理模型：必须绑定"它=阿言"，且回答像人话（无"我不能替他确认状态"式公文腔）。把回答原文贴进施工报告。
