# 权限 · 交付链 · 信誉奖惩 —— 一页拿住（2026-07-09 定版）

> **2026-07-13 勘误**：本文保留当时的设计与测试记录，但不再代表当前可靠性结论。隔离实测确认：`_过交付门` 和 `_过经理收敛` 对“模型审崩/判不清”会拒绝，但对函数内部异常仍返回通过；产出先落盘、待验收后登记；待验收记录只保存路径，不绑定文件哈希。当前事实与修复优先级见 [`公司基础设施实测与风险账_2026-07-13.md`](公司基础设施实测与风险账_2026-07-13.md)。
>
> **2026-07-13 新制度覆盖**：信誉高不得免复核、不得越级。部门头把关 → 经理收敛 → 船主验收三层对所有人固定执行；信誉受限只会在原链路外增加一次独立复核。本文后文出现的“高信誉免复核”均作废。

> 给船主和下一个舟/codex。这套是 2026-07-09 船主亲自逐轮敲定的：公司的**上下级、谁能派谁、活儿怎么一层层交到船主手里、以及怎么让模型真有"奖惩感"**。真谛贯穿始终：**权限焊在平台上（真门，不是提示词）、每样规则绑在房间的规则牌上（跟房间一起插拔）。**

## 00 · 一句话
一件活：**员工干 → 部门头把技术关 → 经理做交付前审查 → 船主验收拍板**；每一步的把关/交付/验收结果都进当事人的**信誉账**，回喂他下次的上下文、并真实地放大或收紧他的**自主度**。上下级、派活权、把关权全焊在各部门/岗位的规则牌上。

## 01 · 上下级（两轴，绑在部门规则牌上）
- **公司级**：船主 ▸ 经理办公室（老钟）▸ 部门头 ▸ 员。
- **部门内**：部门头 ▸ 员。编程部 老梁(首席)›阿强(工程师)；编辑部/测试部/经理办公室 单人，头即本人。
- **声明在哪**：每个部门模块 `工具/部门/<部门>.py` 自己写 `头 = "<岗位>"`；经理办公室额外写 `跨部门权 = True`。加/剪部门＝丢/删一个 .py，注册台 `工具/部门/__init__.py` 自动认，别的部门零改。
- **注册台查询**：`部门头(人名)` / `是部门头(人名)` / `有跨部门权(人名)` / `同部门(甲,乙)` / `可派活(派活人,被派人)`。

## 02 · 分派门（谁能给谁派活）
`平台_工具集.assign_task` 开头读部门规则牌判权（`部门.可派活`）：
- **经理办公室的人（跨部门权）** → 派任何人。
- **部门头** → 只能派**本部门的员**（不能派另一个头/别部门/上级）。
- **员工/单人** → 不能给别人派活（只能请示 / find_colleague / 转办事）。
- **下级不能给上级派活。** 无岗位上下文（船主/大厅直接驱动）时放行。

## 03 · 交付链（三道关，各查各的）
一件活派下去、员工干完（`assign_task` 里 `唤醒本人` 拿到产出）后，依次过：

**① 部门头把关（交付门）** — `_过交付门`
- 员工的产出必过他部门头：**打回**（必附理由，退回不进验收）／**放行**（有话才写评语）。
- 部门头/单人部门/自己是头 → 直接进下一关（无人可审）。
- 查的是**部门内技术对不对**。打回→当事人记忆记一笔＋信誉扣"交付被打回"。

**② 经理收敛（交付前审查）** — `_过经理收敛`
- 部门头放行后、上船主前，非经理派的活先过经理（老钟）。**经理自己派的、或被派人就是经理→跳过**（他本就是收敛者，不重复唤醒）。
- 经理做的是**项目经理交付前审查＝质量控制**（依据 PMBOK "Control Quality"，见 07 出处）：**对照任务当初的要求（＝验收标准）逐条核**——①要求都满足了吗 ②范围对不对（该做没、多做/漏做）③质量达标、拿得出手吗。**达标才放行**，放行可附一句给船主的交接说明。
- **经理≠验收**：经理只做质量控制（替船主把"对照标准逐条核"这件累活干完），**算不算数是船主的正式接受权**。经理核"合格"≠已验收。

**③ 船主验收（正式接受）** — `待验收记录.批准/打回`
- 依据 PMBOK "Validate Scope"：**客户/船主的正式接受**。产出进右栏「待你验收」，船主批了才算正式交付、可打回。这是**最终拍板权，只有船主有**。

> 差别一句话：**部门头查"技术对不对"、经理查"对照要求达标没（质量控制）"、船主查"认不认（正式接受）"。** 三道各挡不同的失败，不重复。

## 04 · 信誉奖惩（让模型真有"感觉"）
真谛（船主 2026-07-09）：模型不吃钱和罚款，但吃"进它上下文的评价"——RLHF 就是拿评价矫正它。所以奖惩＝**把评价闭环在推理期用它读得到的上下文重建**。代码：`信誉.py`。
- **信誉账**（`信誉/<人名>.jsonl`，只由真实结果落账、没人能手工刷）：加分＝验收通过/把关准/挡下真问题/整合一次过；扣分＝交付被打回/放水被抓/反复敷衍。
- **信任等级**：高／中／受限（近 20 条事件加权算；新人默认中）。
- **回喂上下文**：唤醒时 `机房.岗位上下文` 注入本人的信任等级＋最近记录——他带着"上次放水被抓/上次把关准"来干活。
- **复核纪律（2026-07-13 覆盖）**：信誉高只代表近期成绩好，不兑换免检或越级权；固定三层汇报链一层不少。`信誉.需加复核` 只在信誉受限时额外增加一次独立复核。
- **问责闭环**：`待验收记录._记信誉`——放行的活验收通过＝给**部门头＋收敛经理**都记「把关准」；被打回＝都记「放水被抓」。谁放的水，账上查得到。
- **公开（自尊维度）**：`工具间.查在岗` 直接列全员信任等级（同事互见）；`/memory` 后台 JSON 每人带 `信任等级`＋`信誉画像`（船主可见）。

## 05 · 请示 / 审批（越级不存在，走经理汇总）
真谛（船主）：越级不该存在；员工请示先经经理酌情，经理拿不准才汇总船主；船主只对经理一个汇总口。代码：`平台_工具集.ask_owner` + `审批.py`。
- **员工 `ask_owner`** → `创建请示(直接上报=False)` 落「待经理」→ `经理预审`（老钟 gpt-5.5 批/驳/上报）：批/驳→经理自己了结；上报→进「待船主」等船主裁决。（接活了此前空转的 `经理预审` 死代码。）
- **经理本人（跨部门权）请示** → `_直达船主`（他是唯一汇总口）。
- **聊/活消歧**（`转办事` 升级闸）→ `_直达船主`：这是澄清船主自己的话、不是权限请示，不走经理预审。
- **红线**（删除/花钱/密钥/最终交付验收）：本就是船主专属，经员工→经理汇总或经理直达，不越级。

## 06 · 房间/文件地图（这套碰了哪些）
- `工具/部门/`（新，包）：`__init__.py`(注册台＋上下级/派活权查询) + `编程部.py/编辑部.py/经理办公室.py/测试部.py`（各自规则牌：收/头/跨部门权）。个人记忆按人存各自部门目录（`编程部/老梁.md` 等，跟人走）。
- `工具/资料室.py`（新）＋ `资料室/`：公共记忆（`船主.md`/`图谱.db`/`会话摘要.md`），全公司共享。
- `工具/信誉.py`（新）＋ `信誉/`：信誉账＋等级＋画像＋自主度。
- `工具/平台_工具集.py`：`assign_task`(分派门+交付门+经理收敛门)、`ask_owner`(走经理)、`_过交付门`/`_过经理收敛`/`_直达船主`。
- `工具/待验收记录.py`：`新增`(带部门头/收敛经理)、`_记信誉`(问责闭环)、`批准/打回`(信誉钩子)。
- `工具/机房.py`：`岗位上下文` 注入信誉画像；`/memory` 带信任等级。
- `工具/工具间.py`：`查在岗` 公开信任等级。
- `工具/审批.py`：`经理预审` 被 `ask_owner` 接活（原为死代码）。

## 07 · 出处（不是拍脑袋，抄的行业实践）
项目经理"交付前审查"依据 PMBOK 的两阶段：**Control Quality（质量控制）＝团队/PM 对照验收标准与需求内部核对、确认交付物正确完整**（＝经理这道）；**Validate Scope（范围确认）＝客户/干系人正式接受签收**（＝船主验收）。审查要点：满足验收标准、范围合规、质量达标/测过、需求逐条可追溯、内部先验证再提交。

## 08 · 已测（2026-07-09，全用真数据 + mock 模型调用，痕迹清干净）
分派门 8 条规则；交付门 单人直通/放行(带评语)/打回(扣信誉)/部门头问责；经理收敛门 自派跳过/被派是经理跳过/别人派收敛(放行·打回)/双问责；信誉 等级随结果升降+验收钩子落账+上下文真注入；请示 经理直达/员工走经理(批·上报·驳)/真mock端到端/聊活直达；公告栏 查在岗+‪/memory 带信任等级。服务重启多轮 boot 干净。
**对抗测试（2026-07-09，7 agent 并行严测）**：分派门/交付门/经理收敛/信誉/请示/记忆归位/回归共 **346 用例过**，揪出 **6 个边界缺口、全修了验了**——①〔中〕分派门 fail-open（经理能把活派给花名册外的幽灵名字）→ 校验被派人在花名册 ②〔低〕交付门/经理收敛门"打回"只去半角空格，全角空格`打　回`漏判成放行 → 去所有空白再判 ③〔低〕`给某人记一笔` 空名写出 `记忆库/None.md` → 加空名守卫 ④〔低〕信誉分遇坏权重整本账作废 → 按 0 计只丢坏那条 ⑤〔低〕信誉账人名未净化、`../` 可路径逃逸 → 净化文件名。修后复验无回归、boot 干净。

**唯一没跑**：真烧模型的一次完整派活（阿强真写→老梁真审→老钟真收敛→船主验收）——走的是本就在用的 `唤醒/调用` 老机制，只在前后插了门。
