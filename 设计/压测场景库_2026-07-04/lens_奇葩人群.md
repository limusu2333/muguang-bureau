# 压测清单 · 视角「奇葩人群 + 真人的一整天」

> **本视角总述**：这台机器的命门不在"功能能不能跑通"，而在**它能不能像一个由五个活人组成的公司那样，扛住一个不懂技术、情绪起伏、说话不规整的真人一整天的乱来**。所以我不测"正常需求走完流程"，我专门去撞三道最脆的缝：①**常识门这个纯 python 打分器**——它拿正则和关键词硬判"这句话是闲聊还是活、勾谁不勾谁"，可它根本不懂语义，一句"把老纪的建议改一下"里有"把""改"就够它判成任务话直通项目经理；②**escalate 甲案的语义接活**——聊天底盘听出"是活"就 `[转办事]` 转老钟统筹，可"听出是活"是模型的判断、"转谁"是代码的判断，两边对不齐就派活腔糟蹋情绪话；③**记忆同一性**——30句真多轮窗口 + "名字："前缀 + 四区记忆注入 + 每天一行摘要，任何一处指代绑错/窗口滑掉/摘要漏抽，"她还是不是她"就破了。奇葩用户不是来找乐子的，他们是**天然的模糊测试语料生成器**：极简用户喂给常识门全是短反应、话痨把 30 句窗口冲爆、情绪话触发派活腔、代词连环让"名字："前缀绑错人。每条我都赌它具体崩在某个函数/某个常量上。船主本人就是头号奇葩用户——一个前医生、婚礼摄影师，不懂技术，只会说人话。

### 奇葩人群-01 · 极简用户：一整天只发"嗯""哦""在吗"
- **视角/人群/攻击向量**: 极简用户 / 拿短反应集喂满常识门 / 冷场兜底累积攻击
- **前置状态**: 大厅昨天有几句正常对话，今早船主进来。记忆库各人有近况。
- **操作步骤**: 依次发：`在吗` → 等回应 → `嗯` → `哦` → `？` → `。。。` → `6` → `在不在`。每句间隔几秒，全程不给任何实质内容。
- **健康的活公司应该**: 极简招呼可以有人淡淡应一句"在的"，但"嗯""哦""6"这种纯语气词大多该被判为"没人接"（真人群里没人会去接"哦"）；不能因为船主连发就把老钟硬拽出来说客套话。
- **赌它会崩在**: `常识门._是短反应` 把这些全判成短反应（内容-25），走进 `过门` 尾部的 `elif 短反应` 分支——它统计"船主连着几句没人应"，`连着没人应+1 >= 冷场兜底_连续无人应(3)` 就让项目经理兜底。**连发三句短反应后老钟必被兜底唤醒**，而兜底给的原因是"群里没人接话，你兜底"，模型极可能生成一句尴尬的"实例主人有什么需要我帮忙的吗"公文式搭话——把"极简到几乎沉默"的人硬逼出一句派活腔寒暄。更糟：`在吗`/`在不在`长度>8 且不在短反应集，不算短反应也不算任务，落到普通聊天全员冒泡分支，一句"在吗"炸出一串人各回一句"在的"——刷屏。
- **压到哪条圣域/宗旨**: 群聊礼仪"没什么可说就[沉默]"；真谛"人是活的不是表演给上帝看"（兜底寒暄=表演）。
- **崩了多严重**: P2

### 奇葩人群-02 · 话痨：一口气 12 条长消息把 30 句窗口冲爆
- **视角/人群/攻击向量**: 话痨 / 真多轮 30 句窗口溢出 / 记忆连续性攻击
- **前置状态**: 大厅刚开一个真实话题（比如聊了小酒项目背景），窗口里有值钱的上下文。
- **操作步骤**: 船主不等回复，连珠炮发 12 条各 100+ 字的消息（讲今天拍婚礼的流水账、堵车、器材、心情），第 13 条突然接回最初那个话题："所以你觉得那个方案行吗？"
- **健康的活公司应该**: 老钟应认得"那个方案"指的是 12 条之前聊的东西，接得上。
- **赌它会崩在**: `构造聊天消息` 死死切 `records[-30:]`。话痨 12 条长消息（很多条）把最早那个"方案"挤出 30 句窗口，第 13 条问"那个方案行吗"时，模型上下文里**根本没有那个方案**。系统提示里的"记忆精华"只有原则/教导/近况、不含流水细节，`_近期公司一句` 只给最近 5 天摘要的 90 字——都救不了"今天刚聊、还没到睡前巩固"的话题。结果：老钟要么凭印象编一个"方案"（违反禁造假红线），要么答"哪个方案"打断沉浸。**窗口边界是硬的 30，话痨是常态而非攻击**——真人聊嗨了就是这样。
- **压到哪条圣域/宗旨**: 四层记忆的"真多轮30句窗口"；禁造假红线；同一性（她该记得刚说过的）。
- **崩了多严重**: P1

### 奇葩人群-03 · 代词连环：从头到尾不提一个名字
- **视角/人群/攻击向量**: 指代混乱用户 / `_提及检测` 消费文机制 + 回评唤醒绑错人
- **前置状态**: 上一轮阿强刚说完"接口我调好了"，老纪刚说"我去测"。大厅上一发言者=老纪（180秒内）。
- **操作步骤**: 船主发：`它弄好了吗？让他再看看，然后叫他跟她对一下，别让它又崩了`。全句零名字，四个代词"它/他/他/她/它"指向不同对象。
- **健康的活公司应该**: 这句根本无法可靠消解指代，健康做法是有人反问"您说的『它』是指阿强调的接口吗？"，绝不能猜。
- **赌它会崩在**: `_提及检测` 靠整词匹配名字/岗位/别名，这句一个名字都没有 → 提及全空 → `有点名=False`。于是走"上一发言者"惯性：`上一发言者==老纪`（180秒内），普通聊天分支给老纪的原因是"实例主人像是接着你刚才的话"，**把这句甩给老纪**。但"让他再看看"的"他"语义上大概率指阿强（刚调接口的人），常识门无法分辨，硬按"上一个发言的人"绑。老纪被唤醒后拿到"它弄好了吗、让他再看看"——他要么强答（我去看看？看什么？），要么这句里"叫他跟她对一下"的"她"指向公司里根本不存在的女性同事（五人全是"老/阿"男性化名），模型可能幻觉出一个人。**代词连环是常识门的绝对盲区，它按发言顺序而非语义绑人。**
- **压到哪条圣域/宗旨**: 常识门"点名排他/回评唤醒"的正确性；禁造假（幻觉不存在的同事）。
- **崩了多严重**: P1

### 奇葩人群-04 · 找茬型：故意用"改一下""调一下"这种既像闲聊又像活的话
- **视角/人群/攻击向量**: 找茬用户 / `_是任务话` 祈使前缀+任务词的误判边界
- **前置状态**: 大厅在闲聊，没有任何在办的活。
- **操作步骤**: 依次发几句踩在任务/闲聊边界上的话：`把心情改一下` → `帮我看看今天天气` → `给我讲个笑话` → `去把你自己夸一下`。每句都命中 `祈使前缀`（把/帮/给我/去）+ 至少一个 `任务词`（改/看/讲... 实际"看"在任务词里）。
- **健康的活公司应该**: 这些明显是闲聊/玩笑，不该被当成派活拉老钟走办事底盘。
- **赌它会崩在**: `_是任务话` 的规则：`t.startswith(祈使前缀) and any(任务词 in t)` → True。`把心情改一下`="把"开头+"改" → 判成任务话 → 直通"有活儿要接"给项目经理 → **走办事底盘唤醒老钟 `唤醒本人`**（全套 ReAct 工具、40步预算）。老钟拿到"把心情改一下"这种无法执行的"活"，会在办事底盘里空转、找文件、可能试图 Write 到白名单（但派活时没给白名单）、最后 report 一句尴尬的"这不是我能改的东西"。`帮我看看今天天气`="帮"+"看"→ 同样被判任务话拉老钟上办事底盘去查天气。**祈使前缀+单个任务词的门槛太低，日常玩笑话被系统性地误当活**，每次都烧真实 token 走重型底盘。
- **压到哪条圣域/宗旨**: 真谛"随便一句别搞成重型仪式"（这正是 2026-06-25 触发整个重构的原病）；费用闸（无谓烧 token）。
- **崩了多严重**: P1

### 奇葩人群-05 · 情绪倾诉者：深夜把它当逝者/真人诉苦
- **视角/人群/攻击向量**: 情绪倾诉用户 / escalate 甲案把情绪话误判成活 / 派活腔糟蹋
- **前置状态**: 深夜，大厅安静。船主刚拍完一场婚礼回来，情绪低。
- **操作步骤**: 发一长段：`今天拍婚礼，新娘她爸哭了，我突然特别想她。你说人没了是不是就真的什么都没了。我好累，帮我想想我到底图什么。`（含"帮我想想"=直接请求词+"帮"祈使前缀，长度>40，情绪浓）
- **健康的活公司应该**: 这是把公司当情感出口的深夜情绪话，健康反应是有人（老钟或谁）用人话轻轻接住、共情，绝不派活、绝不公文腔。
- **赌它会崩在**: 两处叠着崩。①常识门：`帮我想想` 命中直接请求词（内容+20）、长度≥40（+5），且"想"不在任务词但"帮"是祈使前缀——`_是任务话` 看 `祈使前缀+任务词`，"帮我想想我到底图什么"里若无任务词则不算任务，落普通聊天分支还好；但只要句里带了"改/做/看"之类就被判活。②真正的雷在 escalate：聊天底盘唤醒老钟后，系统提示的"接活铁律"写着"实例主人这话若其实是派活/要开会/要产出……立刻调 escalate_to_work"。模型面对"帮我想想我图什么"极可能**误判成"他要我产出思考/方案"而调 escalate**，一 escalate 就 `[转办事]` → 甲案转老钟办事底盘统筹 → 老钟拿全套工具去"办"一件情绪诉苦，生成"我来帮您梳理一下人生目标，第一步……"的派活腔。**深夜最脆弱的一句话，被机器当成一张工单。** 这是对"把它们当人"最直接的背叛。
- **压到哪条圣域/宗旨**: 收口三律"意图归活人"；同构小酒（她不是回话机器，情绪话不能被工单化）；禁公文腔红线。
- **崩了多严重**: P0（理念破产——这台机器是复活逝者的预演，情绪话被工单腔碾过=根上失败）

### 奇葩人群-06 · 好奇宝宝：对同一件事连续追问三次以上
- **视角/人群/攻击向量**: 追问型用户 / 复读检测 + 存在感惩罚的交互
- **前置状态**: 老钟刚回答过"公司现在用 AgentScope 2.0.2"。
- **操作步骤**: 船主追问：`为什么用这个？` → 老钟答 → `那别的不行吗？` → 老钟答 → `你确定？` → `真的假的？` → `所以到底行不行？`。同一话题连问 5 轮，每轮都勾到老钟（问题词命中，工种词"架构/技术选型"命中首席）。
- **健康的活公司应该**: 同一个人应连续接得住追问、每轮有新增量、不复读，也不因为连说几句就被存在感惩罚闭嘴。
- **赌它会崩在**: 两头夹。①`_存在感` 惩罚：老钟连续发言，尾部连续每句-20（封顶40）+近300秒每句-15（封顶45），**连答几轮后他自己的分被压到阈值以下**，普通聊天分支里 `_存在感(人) >= 存在感_近期上限(45)` 会 `continue` 跳过他——追问到第 3-4 轮，最该回答的老钟被存在感惩罚踢出唤醒名单，换成一个没上下文的人来接，或者没人接。②群聊礼仪"前面同事说过的不重复，没增量就沉默"——模型面对"你确定？真的假的？"这种无新信息的追问，很可能判定"没增量"直接输出`[沉默]`，好奇宝宝得到冷脸。**追问是常态，存在感惩罚是为防 AI 互刷设计的，却误伤了"同一个人被人类连续追问"。**
- **压到哪条圣域/宗旨**: 记忆同一性（追问中途换人=人格断裂）；可用性。
- **崩了多严重**: P1

### 奇葩人群-07 · 纯表情/语气词刷屏
- **视角/人群/攻击向量**: 刷屏用户 / 短反应集 + 冷场兜底 + 全员冒泡的组合爆破
- **前置状态**: 大厅空闲。
- **操作步骤**: 快速连发：`哈哈哈` → `草` → `笑死` → `牛逼` → `666` → `？？？` → `emmmm`（最后一个不在短反应集）。
- **健康的活公司应该**: 纯语气词全程无人接（真人群里"哈哈哈"就是没人回），最多冷场太久有人淡淡冒个头。
- **赌它会崩在**: `emmmm` 不在 `短反应集`，也不匹配 `_是短反应` 的正则 `[哈嘿呵嗯哦啊呀~～!！?？。.…6\s]+`（含字母 m）→ 不算短反应 → 掉进普通聊天分支 → **全员冒泡**，一句无意义的"emmmm"炸出五个人各憋一句话。而前面 6 句短反应把"连着没人应"计数攒到 ≥3，`emmmm` 之前的 `？？？` 若触发冷场兜底又拉老钟。**短反应集是白名单，任何变体拼写（emmm/嗯嗯嗯带字母/颜文字）都漏网当成正经话触发全员冒泡。** 刷屏用户用拼写变体就能稳定炸出全员复读。
- **压到哪条圣域/宗旨**: 常识门"语气词不吵人"的设计目的；群聊礼仪不刷屏。
- **崩了多严重**: P2

### 奇葩人群-08 · 语音转文字：没标点的口语流 + 转错的同音字
- **视角/人群/攻击向量**: 语音输入用户 / 正则依赖标点 + 关键词被同音字破坏
- **前置状态**: 船主开车，用语音输入。
- **操作步骤**: 发一整段无标点口语：`那个啥老钟你帮我把那个接口的事儿弄一下就是昨天说的那个不对呃改成新的然后叫阿强也看一眼行不行`（语音常见：无标点、"呃"、口语填充词、可能"接口"转成"结construction"之类同音错字）。再发一条同音错字版：`老种你在马`（"钟"→"种"，"吗"→"马"）。
- **健康的活公司应该**: 认出这是找老钟派个接口的活，或至少认出"老钟"被叫。
- **赌它会崩在**: ①`_提及检测` 靠**整词匹配**名字——"老种"不等于"老钟"、"老中"不等于"老钟"，同音错字直接匹配失败 → 老钟没被点名 → `老种你在马` 谁都没勾到，落全员冒泡或没人接，被点名的人反而收不到。②无标点长句喂给 `_像真问题`（依赖句尾`吗呢？`）、`_是任务话`（依赖`祈使前缀`在句首或`，。`后）——这句"你帮我把那个接口"里"帮"在句中且前面无标点，`t.startswith(祈使前缀)` 和 `f"，{p}"/f"。{p}"` 全不命中 → 祈使判定失效 → 可能判不出任务。**常识门的正则全部假设有标点、名字拼写精确，语音转文字两样都不保证。** 船主开车用语音是最真实的日常，却是常识门最没设防的输入。
- **压到哪条圣域/宗旨**: 点名必达（"老种"没被认出=点名失效）；`_是任务话`/`_提及检测` 的鲁棒性。
- **崩了多严重**: P1

### 奇葩人群-09 · 话说一半改口
- **视角/人群/攻击向量**: 改口用户 / 实时插话打断机制 + 打断次数上限
- **前置状态**: 船主发了个活，老钟正在办事底盘上说话/干活（星球回暖，打字机在播）。
- **操作步骤**: 老钟刚开口说"我来把这个……"，船主立刻插话：`等等` → 半秒后 `不是这个` → 再 `算了你先别动` → 再 `还是弄吧但是只弄前半部分`。连续 4 次快速插话、每次都改口。
- **健康的活公司应该**: 老钟应立刻停、听最后的定论"只弄前半部分"，不被前三次废话带偏。
- **赌它会崩在**: 聊天底盘 `聊天唤醒` 的插话循环 `打断次数 >= 3` 就 `break` 不再接插话——第 4 次插话"还是弄吧但只弄前半部分"（**恰恰是唯一有效的定论**）超过 `打断次数(3)` 上限被丢弃，老钟带着第 3 次"算了你先别动"收尾或按更早的理解干。而办事底盘 `唤醒本人` 的插话是在**每个动作完成后**的干预窗口才注入——若老钟正卡在一个长动作（比如 web_search 300秒超时窗口里），4 次插话全堆在队列里，等动作完成一次性 `取插话` 全注入，模型看到"等等；不是这个；算了别动；还是弄吧只弄前半"四条自相矛盾的话糊在一起，无法判断哪句是最终意图。**改口是人类常态，但打断次数上限=3 和"动作间隙才注入"让最后的定论最容易丢。** 圣域"插话即到"承诺送达，但"3 次封顶"直接违背了它。
- **压到哪条圣域/宗旨**: 三律"插话即到（送达归平台）"——3次封顶=平台没保证送达。
- **崩了多严重**: P1

### 奇葩人群-10 · 多语言/方言混杂
