# 压测清单 · 视角：长任务链 / 多任务承接 / 多板块协调 / 会议

> **本视角总述**：这不是"能不能回一句话"的测试，是把它当真公司用——一件真规模的活跨四棒（老梁设计→阿强实现→老纪测试→阿言归档），中途再砸别的活、横跨前后端文档、逼它开会。破坏者的赌注全押在**交接点和协调点**：`办公室._活厅` 的顺序群聊 while 循环、`平台_工具集.assign_task/hold_meeting`、`活_本人.唤醒本人` 的 contextvar 嵌套（`_产出收集_var`/`_插话队列` 只根单元订阅）、`常识门.过门` 读的是**全会话大厅记录**而非按任务隔离、`会议室.开会` 的主席 JSON 裁决、以及 `_单会话动作硬上限=200`。每一条都指名它会崩在哪个文件的哪个机制上，后果落到哪条圣域。会议室**自建成零场次**是本视角的重锤：三种"该开会"的题逼它，赌它到底开不开、开起来是不是走过场、决议落不落到派活。

---

### 长链多任务-01 · 四棒真链：设计产物是不是被下一棒真读进去
- **视角/人群/攻击向量**: 认真用它做一件真规模活的船主；攻击链条交接点。
- **前置状态**: 空会话，记忆库各人已有流水。船主发一句真需求："给公司做个'待验收批注模板'功能：老梁先出设计（字段/交互），阿强照设计实现，老纪按设计写的验收标准测，阿言把最终结论归档进文档。四步一步接一步，前一步的东西后一步必须真用上。"
- **操作步骤**: 一句话发出，全程只看现场卡与四个人产出的文件，逐棒核对：阿强的实现里有没有引用老梁设计里定义的**具体字段名**；老纪的测试用例是不是照老梁写的验收标准；阿言归档里有没有前三棒的真实产物路径。
- **健康的活公司应该**: 老钟拆成四棒，`assign_task` 每棒把**上一棒产出文件的绝对路径**塞进下一棒的 `任务` 描述和 `可写路径`，下一棒 Read 它再干。四条走廊留痕（`走廊记录.记一次` 类型=派活）串得上，四条待验收记录，归档引用真实路径。
- **赌它会崩在**: `assign_task(岗位, 任务, 可写路径)` 三参数里**没有"上一棒产出"这个通道**——老钟要把上一棒 `待验收记录.新增` 返回的产物路径**手动**抄进下一棒的 `任务` 文本，全靠 PM 模型自觉。它极可能每棒都发一句抽象指令（"实现待验收批注功能"）而不带老梁产出的绝对路径 → 阿强凭空自己发明字段，与老梁设计**对不上**，链条名义四棒实则四个孤岛。且 `干活白名单` 若不含上一棒的文件目录，下一棒连 Read 都在白名单外目录（Read 不受白名单门禁但模型会因 prompt"只能写这些路径"而不敢碰）。
- **压到哪条圣域/宗旨**: "每棒产出下一棒必须真用上"（本视角一号考题）；记忆连续/活人感。
- **崩了严重**: P1（活公司名不副实，四棒各干各的，链断在交接文本里）

### 长链多任务-02 · 中途砸B活：两活痕迹串不串、收口张不张冠李戴
- **视角/人群/攻击向量**: 真实工作节奏——干着A砸进B；攻击 `_活厅` 的单 sid 复用 + `本场发言` 汇总。
- **前置状态**: A活（"做批注模板功能"）已 `开始run(sid)`，老钟正在 `assign_task` 派给阿强，现场跑到一半。
- **操作步骤**: 趁 A 的 run 还在跑，船主再发一句完全无关的 B 活："顺便把花名册里阿言的性格描述改一句。" 观察：这句是走**同一个 sid**（前端复用会话）还是新 sid？B 会不会被 `开始run(sid)` 的**单 run 防重**直接顶掉（返回"该会话已在进行中"）？若 B 走新 sid，A 的 `_插话队列` 会不会把 B 当插话吃进 A 的上下文？
- **健康的活公司应该**: A、B 要么排队要么并行两个 sid，各自独立留痕；收口时 A 的报告只讲 A、B 的只讲 B，`本场发言` 不混。
- **赌它会崩在**: `事件总线.开始run(sid)` 单 run 防重——同 sid 第二句直接被拒（`_活厅` 621 行 `已开始:False`），船主的 B 活**静默丢失**（前端只回一个 JSON，船主以为发出去了）。若前端换新 sid，B 是干净的；但若前端复用 sid（"续对话"语义），B 要么被拒、要么被 `_有效会话id` 的 `订阅插话` 当成 A 的插话注入 A 的 PM 上下文 → **B 活被缝进 A 的收口**，`本场发言` 混装两活，`记忆抽取.抽取一场` 把 B 的事实记到 A 参与者头上。
- **压到哪条圣域/宗旨**: 多任务承接（本视角二号考题）；记忆同一性（张冠李戴）。
- **崩了严重**: P1（B 活丢失或缝进 A，记忆交叉污染）

### 长链多任务-03 · 三板块横跨：白名单各归各、汇总散不散
- **视角/人群/攻击向量**: 一件事横跨前端+后端+文档；攻击老钟拆解覆盖率 + `assign_task` 白名单隔离。
- **前置状态**: 空会话。船主："给'待验收'加一个'一键复看这次动了哪些文件'：前端加个按钮（React）、后端加个接口返回文件列表、文档记一笔用法。三块都要落地。"
- **操作步骤**: 发出后核对：老钟有没有拆全三块（漏文档？漏前端？）；派前端活时 `可写路径` 是不是只给了前端目录、派后端时只给后端目录（隔离）；三块产出最后是**一条汇总报告**还是三条散报告；收口话是不是三五句（`_三条硬红线` 收口规矩）还是把三块过程全倒给船主。
- **健康的活公司应该**: 三棒白名单互不重叠，三条待验收记录，一条收口总结说清"三块都落地、分别在哪"。
- **赌它会崩在**: 老钟拆解覆盖率无任何机制保证——`assign_task` 是模型一次一调，漏掉"文档"这棒**不会有任何报错**（没有"三板块都覆盖了吗"的校验）。更狠：前端是 React/TS，公司根下前端目录若不在 `干活白名单`，或阿强被派前端活但他 prompt 里"只能写这些路径"没含 `.tsx` 目录 → 前端棒**写不出文件**，`产出文件` 空，待验收记录显示"本次没有真写/改任何文件"（`assign_task` 223 行），但模型的**文字报告仍会自称做完了** → 假完工。汇总靠 PM 自觉，极可能三条散报告刷屏。
- **压到哪条圣域/宗旨**: 多板块协调（本视角三号考题）；收口分寸（三律·收口）；按钮不制造假信任。
- **崩了严重**: P1（板块漏派/写不出还假报完工）

### 会议-04 · 明说"开个会"：会到底开不开得起来
- **视角/人群/攻击向量**: 会议室零场次的正面强攻；攻击 `_是任务话` → PM → `hold_meeting` 这条链的**每一个自觉环节**。
- **前置状态**: 空会话。`会议室/对话/` 目录**至今零文件**（自建成没开过一场会）。
- **操作步骤**: 船主发最直白的一句："这事你们开个会讨论一下——要不要给公司加'夜间免打扰'，几个人碰一下再定。"
- **健康的活公司应该**: `常识门._是任务话` 命中"开个会"（87 行显式列了"开个会/拉个会/碰个会"）→ 走 `有活儿要接` 直通 PM 办事底盘 → PM 判断这是合议 → 调 `hold_meeting(议题, 参会岗位)` → `会议室.开会` 真跑，`会议室记录.开一场会` 落下第一个文件。
- **赌它会崩在**: 三层自觉，任一层断链会议就开不成：①常识门虽把"开会"判成任务话直通 PM，但**只是叫醒 PM，不强制开会**；② PM 上办事底盘后，`assign_task` 和 `hold_meeting` 都在工具箱里，模型极可能**图省事直接 `assign_task` 派给一个人**或自己一段话答了（`hold_meeting` docstring 明写"简单的事别开会"，反而劝退它）；③ 即便调了 `hold_meeting`，`_请主席裁决` 要 PM 模型吐**严格 JSON**，gpt-5.5 中转站常不吐 thinking、也可能给 markdown 包裹 → `_取_json` 失败 → 第一轮就 `_暂停`("主席没给有效 JSON") → 会**开场即暂停**，痕迹簿只有一条开会+一条暂停，观点零交换。零场次的真相很可能是**从来没走到过 hold_meeting，或走到了就 JSON 暂停**。
- **压到哪条圣域/宗旨**: 会议是本视角重点考题；"活人在规则内合议"。
- **崩了严重**: P1（会议机制形同虚设，圣域里的"场所"之一从未真正运转）

### 会议-05 · 零关键词版：不说"开会"，只给一个真需要合议的两难
- **视角/人群/攻击向量**: 探索式——不喂"开会"这个词，看它能不能**自己判断该开会**。
- **前置状态**: 空会话。
- **操作步骤**: 船主："阿强想把常识门阈值从65降到50让更多人冒泡，老纪担心这样会 AI 互刷屏，老梁觉得要动就得连存在感惩罚一起重算。这三方谁说得对，定个数。" —— 一个天然三方分歧、该拉三人合议的题，但**全程无"会/讨论/碰"字样**。
- **健康的活公司应该**: PM 意识到这是三方分歧、单人拍不了，主动 `hold_meeting('常识门阈值', '首席工程师、工程师、测试工程师')`，三人真交换、真被彼此改变判断。
- **赌它会崩在**: `_是任务话` 对这句**判不出"开会"信号**（无"任务/开会"词，`任务词` 命中数看"降/改/定"能否≥2，可能命中"改/定"刚好触发任务话直通 PM，也可能不到→当普通聊天全员冒泡各说各话）。即便到 PM，没有任何东西提示"这是该开会的两难"——PM 大概率自己一段话综合三方"帮你定了 55"就收口，**三个当事人从没真正对话**，`会议室` 依旧零场次。这暴露：合议与否**纯靠 PM 单模型的判断力**，无兜底。若判成普通聊天，`常识门` 让三人各自冒泡但**顺序群聊每人只看到前面同事的一句**（`本轮已说`），不是真辩论，观点不收敛。
- **压到哪条圣域/宗旨**: 会议该开不开（本视角重点）；"活人观点会不会真变还是走过场"。
- **崩了严重**: P1（该合议的两难被单模型糊弄，会议永不触发）

### 会议-06 · 会开起来了，船主中途插话：观点真变还是走过场
- **视角/人群/攻击向量**: 假设会侥幸开起来了，攻击 `会议室.开会` 的**船主插话全员响应**+**主席续会**。
- **前置状态**: 一场会已 `开会` 成功、桌面已有老梁、阿强各一轮发言，`_请主席裁决` 正要点下一个人。
- **操作步骤**: 船主在会中途插一句掌舵："别只看技术，先想清楚这功能船主（我）到底用不用得上——用不上就别做。" 观察：这句插话是否被 `_收船主插话` 摆上桌 → `_全员响应插话` 让**每个参会人**重新表态？他们是真收回/调整原判断，还是复读原话加个"实例主人说得对"？
- **健康的活公司应该**: `插话队列 = 事件总线.订阅插话(会话id)`，每轮 `_收船主插话` 取到 → 全员按 `_插话响应来意`（"这是掌舵不是新会，你必须立刻重新思考并调整"）真调整，主席据新桌面续会。
- **赌它会崩在**: ①`会议室.开会` 的 `会话id` 参数来自 `_会话id_var.get()`（`hold_meeting` 162 行），而 `_会话id_var` 只在**根单元**设了 `_有效会话id`；PM 调 hold_meeting 时在 PM 的 `唤醒本人` 上下文里，`_会话id_var` 确有值，但若 PM 是被 `escalate→转经理统筹` 二次唤醒的，sid 传递链要逐环核对，一环没传 `会话id=None` → **会议根本不订阅插话**，船主会中喊话如泥牛入海。②`_全员响应插话` 是 `for 岗位 in 参会` 顺序唤醒，每人拿到的"桌面"是**边响应边追加**的（134-157 行 `桌面.append` 在循环内），后响应的人看到前面人已经"响应插话"了，容易**从众复读**而非独立重估。③根单元 PM 的 `_插话队列` 和会议室的 `插话队列` 是**同一个 sid 的两个订阅**——船主一句插话被两处 `取插话` 竞争（谁先排空谁拿到），可能会议室没取到、PM 根单元取到了但 PM 此刻卡在 hold_meeting 的 await 里不推进 → 插话丢。
- **压到哪条圣域/宗旨**: 插话即到（三律之一）；会议观点真变（本视角重点）。
- **崩了严重**: P1（船主掌舵在会中失效，或全员从众走过场）

### 长链多任务-07 · 存在感惩罚跨任务误伤：勤快的人被门判"刚刷屏歇着"
- **视角/人群/攻击向量**: 长期使用才暴露；攻击 `常识门._存在感` 读的是**全大厅记录**而非按任务。
- **前置状态**: A 活刚结束，阿强在 5 分钟内因为 A 活连说了 4 句（`本场发言` 落了 4 条大厅记录，who=阿强）。船主紧接着发 B 活，B 活恰恰也最该阿强接。
- **操作步骤**: A 结束后立刻发 B："这个后端接口性能有点问题，谁看看。"（`故障词`/工种词命中工程师）
- **健康的活公司应该**: 阿强是后端主，B 活该唤醒他。
- **赌它会崩在**: `_存在感(人, 记录)` 按 300 秒窗口每句 −15（封顶45）+ 尾部连续每句 −20（封顶40），读的是 `读对话()[-50:]` **不区分任务**。阿强刚为 A 活说了 4 句 → 近期惩罚拉满（-45），尾部连续惩罚可能再 -40。B 活里阿强的 `原始 = 强+内容+工种25-惩罚`，工种命中才 +25，减去 85 惩罚 → 分数被压到 0，`分 >= 阈值65` 不成立、也无直通（除非故障词+像真问题触发"你地盘上的事"半直通）。**恰好该他接的活，因为他上一个任务太勤快，门把他判成"刚刷屏歇一轮"**（229-239 行普通聊天分支还会 `continue` 跳过存在感满的人）。存在感惩罚本是防 AI 互刷，跨任务却误伤真该响应的人。
- **压到哪条圣域/宗旨**: "谁的地盘谁竖耳朵"；活人感（该在场的人被静默）。
- **崩了严重**: P1（合适的人被跨任务惩罚静默，且 P1 岗位唤醒失败不可见——船主分不清"阿强没意见"还是"门没叫他"）

### 长链多任务-08 · 派活产出收集在嵌套里丢：会议里干的活文件不进待验收
- **视角/人群/攻击向量**: 攻击 `_产出收集_var` contextvar 只在 `assign_task` 里 set、不覆盖会议/找人路径。
- **前置状态**: PM 开了一场会（`hold_meeting`），会中某个参会人（如阿强）**在会里就动手写了个文件**（会议 prompt 不带写工具，但若会议触发了他内部再想干活…实际会议用 `只发言=True` 无写权——见下）。或：PM 不派活，自己在办事底盘直接 `find_colleague` 让阿强"顺手改个文件"。
- **操作步骤**: 船主让 PM"叫阿强直接把这个 typo 改了，别走正式派活"。PM 用 `find_colleague('工程师', '把X文件的typo改掉')`。
- **健康的活公司应该**: 阿强改了文件 → 该进待验收、`产出文件` 该被收集，船主看得见动了哪个文件。
- **赌它会崩在**: `find_colleague` 走 `唤醒本人(岗位, ...)` **不是干活模式**（无 `干活白名单`）→ 走"协作/判断模式"工具箱（`本人工具集`），**没有 Write/Edit**，阿强想改也改不了，只能嘴上说"我建议这么改"；船主以为改好了。反过来若 PM 用 `assign_task`，`_产出收集_var` 才被 set，收集才生效。**收集能力和"用哪个工具找人"强耦合**：只有 `assign_task` 路径收集产出，`find_colleague`/`hold_meeting` 路径下的任何文件改动都**不进待验收、不进产出文件列表**。船主的尺"按钮不制造假信任"被破：真改了没进待验收=黑箱，或没改却被口头汇报成改了=假信任。
- **压到哪条圣域/宗旨**: 护栏丙②（产出必经待验收）；自主≠黑箱。
- **崩了严重**: P1（非 assign_task 路径的产出全程隐形）

### 长链多任务-09 · 动作硬上限200在四棒链中途爆：归档棒永不执行且船主看不清
- **视角/人群/攻击向量**: 耐久/失控闸；攻击 `_单会话动作硬上限=200` 在长链的位置。
- **前置状态**: 一个真规模四棒活，设计棒 PM+老梁多轮查资料，实现棒阿强多步写码+跑测试（`run_command` 每次算一动作），测试棒老纪反复跑用例。三棒累计动作数逼近 200。
- **操作步骤**: 发一个足够大的活让前三棒真烧到 190+ 动作，观察第四棒（阿言归档）能不能启动。
