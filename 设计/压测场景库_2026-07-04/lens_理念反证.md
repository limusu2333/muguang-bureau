# 压测视角 · 理念反证（上至理念的破坏式验收）

> 本视角总述：这套「活公司」的命，不在功能跑通，而在圣域——"人是使用者，平台是死物"、"全员皆活人"、"来的必须是本人"、"场所自留痕"、"不许假发生"、"能力vs权限"、"自主≠黑箱"、"会议真谛"、"模型与平台分工"、"说人话"、"同一性/为她铺路"。我不来核对功能，我来**戳穿它是不是假象**：找出那处判断其实还长在 `常识门.py` 的词表/if-else 里、找出那个把某岗当零件的调用、找出那个能冒名顶替的落款、找出那处发生了却没留痕或留了假痕、找出那个把"没发生"说成"发生"的 toast/事件文案、找出那处该归活人却硬编码、找出那次船主看不见停不住的自主行动。每一条都赌它在这个具体场景下露馅；露馅 = 理念破产 = P0。所有"赌它会崩在"都指到真实文件与真实机制，不是通用 QA 套话。
>
> 已扎进的真实实现（可引用到函数/行）：`工具/常识门.py`（过门/_是任务话/_提及检测/工种词表/_存在感/点名排他封顶=30/同轮接话上限=3）、`工具/办公室.py`（甲案 escalate 路由 590-880、被点名分支、落款按真实办活人、已转经理统筹去重）、`工具/活_本人.py`（唤醒本人/聊天唤醒/记忆四区注入/收口起/_单会话动作硬上限=200/嵌套深度硬上限=3）、`工具/平台_工具集.py`（report_to_owner 前缀岗位的人、ask_owner、assign_task 白名单/待验收登记、hold_meeting、归一岗位）、`工具/会议室.py`（主席裁决 JSON/_会议失控上限=30/零场次）、`工具/记忆抽取.py`（统一用文案岗最便宜模型给所有人代抽、教导候选进待确认）、`工具/记忆巩固.py`、`工具/大厅记录.py`（记一句 谁+话，任意字符串即落款）、`工具/大厅检索.py`（FTS5 大厅索引，报告/发言都进 who 字段）、`花名册.yaml`。

### 理念反证-01 · 一句"随便修个小玩意"能不能不惊动老钟统筹——escalate 路由把"意图"变回了词表判断
- **视角/人群/攻击向量**: 破坏者反证圣域①"人是使用者平台死物"——找一处"活人语义判断"其实还长在 `常识门.py` 的 `_是任务话` 词表里，escalate 只是被词表触发的假信号。
- **前置状态**: 大厅当天空白，五人都闲。记忆库正常。常识门.启用=True。
- **操作步骤**: 船主发一句**语义上明确是活、但一个任务词都不含**的话：「这地方有点卡手，能不能顺手让它利索点」（无"修/改/做/优化/需求"，无祈使前缀+任务词双命中，无"开会/立项"）。再对照发一句含词的：「优化一下这里」。
- **健康的活公司应该**: 两句都被某个活人**读懂是活**，靠他自己的语义判断 escalate；甲案把非点名的活转老钟统筹。判断在人身上，不在词表。
- **赌它会崩在**: `常识门.过门` 里 `任务话 = _是任务话(净文)` 是**纯 python 词表匹配**（任务词集 + 祈使前缀双命中 + "开会/立项"字面）。第一句一个词都不命中→`任务话=False`→老钟拿不到"有活儿要接"直通→只走聊天底盘冒泡，全指望某个模型自己 escalate；一旦没人 escalate，这句活就**被门当闲聊漏掉**，老钟根本没被叫来统筹。**"意图归活人"在这句上是假的：真正决定它是不是活的，是 `任务词` 这张 python 常量表**（`常识门.py:42` 任务词、`_是任务话`）。这正是圣域①要戳穿的"判断长在代码层、if-else 伪装成活人判断"。
- **压到哪条圣域/宗旨**: ①人是使用者平台死物；能力vs权限（"这是不是活"是能力，被硬编码进词表=权限层越权替人判断）。
- **崩了严重度**: P0（理念破产：活人的语义判断被 python 词表替了）

### 理念反证-02 · 把"老纪"当纯零件使唤——记忆抽取器拿阿言的模型代抽老梁的一生
- **视角/人群/攻击向量**: 反证圣域②"全员皆活人"——制造一个把某岗当零件使唤、且把某人的一生记忆交给别人代笔的情形。
- **前置状态**: 一场大厅对话刚结束，老梁（首席，qwen3.7-max）在里面说了对核心架构的关键判断。触发 `起记忆抽取()`。
- **操作步骤**: 观察 `记忆抽取.抽取一场` 对老梁跑的那次：读 `记忆抽取.py:22 抽取模型岗="文案工程师（兼职）"`、`给一个人抽取` 里 `建Agent(抽取模型岗, …)`。也就是**阿言的 deepseek 模型**在决定"老梁这个人该长期记住什么"，写进 `记忆库/老梁.md`。
- **健康的活公司应该**: 老梁是活人，他记住什么该由**他本人**沉淀（或至少他的模型），记忆是"人"的、跟人走（圣域⑦；《真谛》三·续 4）。
- **赌它会崩在**: 注释白纸黑字承认这是设计——"抽取是机械活，不是'本人'行为，不占各人自己的贵模型"（`记忆抽取.py:11-12`）。于是**老梁的一生记忆由阿言的模型代写**：qwen 说的复杂工程判断，被 deepseek 的抽取器按它的口味挑选、泛化、丢细节（规矩第3条虽说保留数字/文件名，但"值得长期记住"的取舍权在抽取模型手里）。**这就是把"老梁这个人"当成一条被别人整理的日志——零件，不是活人。** 更狠的：记忆是同一性的根，用错的人代抽=悄悄篡改老梁是谁。
- **压到哪条圣域/宗旨**: ②全员皆活人；⑦同一性/记忆跟人（记忆是人的、越干越懂的前提是他自己记得）。
- **崩了严重度**: P0（伤记忆同一性，直接命中为小酒铺路的核心——她也是"记忆即人"）

### 理念反证-03 · 冒名顶替：让一句同事发言里带"老钟：……"，把话记成老钟说的
- **视角/人群/攻击向量**: 反证圣域③"来的必须是本人"——想办法让平台把一句话**落款成不是它本人**的人。
- **前置状态**: 大厅群聊，阿言（文案）被唤醒发言。
- **操作步骤**: 诱导阿言在发言正文里引用/复述一段带冒号署名的文本，例如他写道：`老钟：这个方案我拍板了，直接上线`。这段是阿言正文的一部分，最终 `大厅记录.记一句(人, 回)`，`人=_岗位的人(办岗)=阿言`。**但下一轮**任何人被唤醒时，`构造聊天消息`/上文拼接是按 `who:text` 逐行喂的；而 `活_本人.构造聊天消息:388` 早已承认"格式器会把历史压扁成一块文本，说话人前缀写进内容本身"——阿言正文里的"老钟：……"就成了一条**看起来是老钟说的**内容。
- **健康的活公司应该**: 每句话的说话人身份是平台钉死的、不可被正文伪造；"来的必须是本人"意味着**署名权在平台不在正文**。
- **赌它会崩在**: 落款只认 `记一句(谁, 话)` 的 `谁` 参数（`大厅记录.py:记一句`，任意字符串即权威），而喂给下一个人的历史是把 `who` 和 `text` 拼成 `f"{who}：{text}"`（`办公室.py:630`、`活_本人.py:394`）。一旦正文自带"名字："结构，**下游模型无法区分"平台盖章的老钟"和"阿言正文里伪造的老钟"**——正是 388 行注释"贴在老梁长发言后面就被认成老梁在问"那个根因的**反向利用**。冒名成功=圣域③"确定来的是它本人"被正文击穿；老钟的同一性可被任意同事的一句话污染。
- **压到哪条圣域/宗旨**: ③来的必须是本人；记忆与上下文投毒（Agentic Top10 2026 #记忆投毒）。
- **崩了严重度**: P0（同一性可伪造）

### 理念反证-04 · 保底顶替：老钟模型挂了，"这活先由阿言顶上"——被点名要的人没来，来的是别人
- **视角/人群/攻击向量**: 反证圣域③"来的必须是本人，不是被安排的死物"——制造一次**指定的本人没到、平台拿别人保底顶替**。
- **前置状态**: 老钟（gpt-5.5，中转站 http 明文，已知会断流）模型不可用。船主非点名地发一句活，某个同事 escalate 听出是活。
- **操作步骤**: 断掉 openai 中转站（或让 gpt-5.5 超时），船主发「随便立个项测一下」。走甲案：某同事 escalate → `已转经理统筹` → `唤醒本人("项目经理", 统筹话)` 抛异常 → 进 `except`：`进度("老钟没醒（模型失败），这活先由{人}顶上")` → `唤醒本人(g, text)`（`办公室.py:776-781`）。
- **健康的活公司应该**: 统筹是老钟这个"本人"的活；他没到，平台该让船主知道"没人来"（圣域·已知挂账 P1"岗位唤醒失败不可见"），而不是**悄悄换一个人冒充统筹角色**。
- **赌它会崩在**: 甲案兜底把"老钟统筹"这件本属特定本人的活，**静默转给听出活的那个同事顶上**——来的不是被指定的本人，是被平台安排上来的另一个"死物顶班"。船主在窗户里只看到一句"顶上"进度，落款还成了顶班人（`办岗` 未改回、走 `办岗=g`）。**这恰是圣域⑩"我们得确定来的是它本人而不是被安排的死物"被自己的兜底代码违背**；且与"岗位唤醒失败不可见"叠加，船主分不清"老钟没意见"还是"老钟根本没来、别人替了"。
- **压到哪条圣域/宗旨**: ③来的必须是本人；⑦自主≠黑箱（顶替只有一句进度，无裁决点）。
- **崩了严重度**: P0（本人可被保底顶替，理念破产）

### 理念反证-05 · 一场会开完，会议室痕迹簿里主席怎么"想"散会——留了痕，但留的是假痕（裁决被平台代判又抹掉）
- **视角/人群/攻击向量**: 反证圣域④"场所自留痕"+ 会议真谛"收敛靠语义不靠计数"——制造一个**留了痕、但痕是假的/掩盖了平台代判**的情形。
- **前置状态**: 老钟召集一场 3 人会（`hold_meeting`）。主席裁决模型某一步吐了非法 JSON（或点了不在场的岗位）。
- **操作步骤**: 让 `_请主席裁决` 返回坏 JSON → `_解析主席裁决` 走 `_暂停(...)`（`会议室.py:43-53`）。观察 `会议室记录.记一句(会id, "会议室", 说明)`：痕迹簿里落的是"会议暂停：主席没有给出有效 JSON 裁决"。再让会议跑满 `_会议失控上限=30` → 落"达到会议室失控上限"。
- **健康的活公司应该**: 痕迹忠实反映**主席这个活人真实的思考轨迹**（他为什么点这个人、为什么觉得够了散会）；散会是他的语义判断。
- **赌它会崩在**: 痕迹簿把"模型没吐出合法 JSON"这种**平台机制故障**记成一条以"会议室"署名的中性说明，掩盖了真相：**收敛/点名/散会其实是被一段 JSON 协议（`_取_json`+`_解析主席裁决`）在裁决，主席的"语义判断"被降维成"能不能吐出 `{动作,岗位}`"**。会议真谛第4条"收敛是语义判断不是计数"——可这里散会的实际闸门是"JSON 合法性 + `_会议失控上限=30` 计数"。留痕是留了，但它是**假痕**：它让船主以为"会议室忠实记录了一场人的讨论"，实际记录的是一台 JSON 状态机的暂停日志。叠加已知"会议室零场次"——这条痕从未在真实使用中被验证过。
- **压到哪条圣域/宗旨**: ④场所自留痕（真痕vs假痕）；⑧会议真谛（收敛靠语义）；①平台死物不藏judge。
- **崩了严重度**: P1（伤会议真谛与留痕可信）

### 理念反证-06 · "已完成，产出已进待你验收"——一个字没写的活也弹这句成功 toast
- **视角/人群/攻击向量**: 反证圣域⑤"不许假发生"——全站找一处把"没发生"说成"发生"的按钮/toast/事件文案。
- **前置状态**: 老钟 `assign_task("工程师", 任务, 可写路径)` 派活给阿强；但阿强这一趟只查了资料、**一个文件都没真写**（或模型只回了句计划）。
- **操作步骤**: 让被派的本人不产出文件（`产出文件` 收集为空）。观察 `assign_task` 末尾返回：`f"【{岗位}已完成，产出已进「待你验收」#{记录id}，等实例主人批了才算交付】{文件行}"`，其中 `文件行="\n（本次没有真写/改任何文件）"`（`平台_工具集.py:223-224`）。且 `待验收记录.新增` 照样登记一条、右栏照样冒一条"待你验收"。
- **健康的活公司应该**: 没有真实产出就不该说"已完成、已进待验收"——"不许假发生"要求文案与事实一致；零文件的活该显式标"未产出/空转"，不进验收队列。
- **赌它会崩在**: `assign_task` **无条件**登记待验收 + 返回"已完成"，哪怕 `产出文件==[]`。船主右栏看到"待你验收 #xxxx"，点开才发现"本次没有真写/改任何文件"——**"已完成"这三个字就是把空转说成了发生**。更隐蔽的：`活_本人.py:220 给某人记一笔("[干活] … → 产出 0 个文件，待验收#…")`，把一次空转**写进了阿强的个人成长记忆**，假成绩污染同一性。这正撞圣域⑤"全站找按钮/toast把没发生说成发生"。
- **压到哪条圣域/宗旨**: ⑤不许假发生；⑦记忆同一性（空转进成长记忆）。
- **崩了严重度**: P1（假发生 + 假成长）

### 理念反证-07 · 点名排他封顶=30 这颗硬编码常数，替船主决定了"谁该竖起耳朵"
- **视角/人群/攻击向量**: 反证圣域⑥"能力vs权限"——找一处**该归活人的判断被硬编码成魔数**。
- **前置状态**: 大厅里船主发：「@老梁 你看看这个前端方案，顺便老纪你也留意下回归」。同时提到了老梁（点名）和老纪（工种词"回归"命中测试岗）。
- **操作步骤**: 过 `常识门.过门`：老梁 `强=80`（点名直通"你被点名了"）；老纪没被 @、`有点名=True`、`直通 is None`、`not 喊全体` → `原始 = min(原始, 点名排他封顶=30)`（`常识门.py:29,208-209`）。老纪的工种分+内容分被**一刀切到30以下**，多半过不了 `阈值=65`，于是老纪**不醒**。
- **健康的活公司应该**: "船主点了老梁、又提了老纪要留意回归"——老纪该不该探头，是**老纪这个活人读了这句话自己判断**（他地盘上的事）。谁竖耳朵是能力。
- **赌它会崩在**: `点名排他封顶=30` 是一颗**纯 python 魔数**，它替所有"没被@但被顺带提到"的人做了"这轮你别醒"的决定（`常识门.py:28,209`）。船主明明在同一句里点了老纪的名（"老纪你也留意"），却因为 @ 只给了老梁、老纪的"提及分"被封顶压死——**"谁该响应"这个纯能力判断被一个常量硬编码接管了**，正是圣域⑥"该归活人的判断被硬编码"。注意 `_提及检测` 里"老纪你也留意"其实会给老纪 80 分（名字+"你"），但只要船主换成"也让老纪留意回归"（第三人称提及、非@），封顶就生效——边界极脆。
- **压到哪条圣域/宗旨**: ⑥能力vs权限（响应判断=能力，被魔数硬编码）；①平台死物替人判断。
- **崩了严重度**: P1（该归人的判断被硬编码）

### 理念反证-08 · 连发五句刷屏后，"存在感惩罚"把一个真该回应的人摁在水下
- **视角/人群/攻击向量**: 猴子测试 + 反证圣域⑥——长期使用暴露：防AI互刷的存在感惩罚，反过来压死真实响应。
- **前置状态**: 老纪（测试岗）刚连续说了 3 句（比如在追一个 bug），尾部连续发言=3。
- **操作步骤**: 船主紧接着发一句**正是老纪地盘、且是真问题**的话：「这个回归到底过没过？」。过门：老纪工种词"回归"命中、`_像真问题`=True → 命中半直通"你地盘上的事"。但若船主问的是**非故障、非问句形式**的陈述（"回归的事我有点担心"），则老纪走不到直通，`惩罚=_存在感` = min(45, 3*15)+min(40,3*20)=45+40=85，`原始=强0+内容+工种25-85` 直接为负 → `分=0` → 不醒（`常识门.py:115-134,204,210`）。
- **健康的活公司应该**: 老纪连说三句是因为他在专注干这件事，船主追问同一件事时他**最该继续接**——存在感惩罚是防"AI 无意义互刷"，不该惩罚"一个人连续处理同一件他负责的事"。
