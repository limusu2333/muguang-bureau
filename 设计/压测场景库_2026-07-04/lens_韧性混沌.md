# 压测清单 · 视角：韧性 / 混沌工程 / 无声失败猎杀

> 本视角总述：我不是来核对"功能正常"的。我来赌这台机器**会不会无声无息地坏**——进程被杀、模型断流、key 失效、两句话并发、坏 JSON 行、急停、跨天。验收铁律只有一条：**坏可以，坏得没声音不可以**。船主必须永远分得清"没意见"和"没人活着"。每条场景的重点都在「赌它会崩在」那一行——那是我真正下注的地方，钉在具体函数/文件/后果上。已通读 办公室.py / 事件总线.py / 活_本人.py / 常识门.py / 记忆巩固.py / 执行室.py / 待验收记录.py，下面每一注都指得回真实代码。

### 韧性混沌-01 · 干活干到一半 kill 服务器，重启后活假完成没、痕迹丢没
- **视角/人群/攻击向量**: 混沌工程·杀进程（daemon 线程丢活挂账 P0 的现场复现）
- **前置状态**: 大厅已有若干句往来；船主发一句实打实的活（"@老梁 把执行室超时从 180 改成 240 并跑一遍自检"）；`唤醒本人` 进了干活底盘，`reply_stream` 正在第 2 个 Write 和 run_command 之间，事件总线里已落了「动作开始/动作完成」若干行，`大厅记录` 已记了 PM 的统筹话但办活人的收口还没落。
- **操作步骤**: 在办事底盘 Write 完成、report_to_owner 之前 `kill -9` 掉 `办公室.py` 进程。等 3 秒重启 `python3 工具/办公室.py`。前端用同一个 sid 重连 `/stream?sid=会xxx`。看：①大厅痕迹簿里这半截活是什么状态？②`/stream` replay 出来的最后一条事件是「立项完成」还是停在「动作完成」？③待验收里有没有登记这条产出？
- **健康的活公司应该**: 重连后 replay 到断点为止，明确显示"这活断在半路、没有立项完成事件"；绝不显示成已交付；船主一眼看出活没干完。
- **赌它会崩在**: `办公室.py:658 跑()` 是 `daemon=True` 线程——`kill -9` 后 `finally`（872-874 `结束run`/`loop.close`）**永远不执行**，于是事件总线里既没有 `run结束` 也没有 `立项完成`。重启后 `事件总线._会话` 从 jsonl `_载入持久`，`SSE流`（141）replay 完就 `订阅` live 挂着等——因为 `s.running` 冷启动是 False，永远等不到 `run结束`，前端**卡在"思考中"的假活状态**：它看起来像还在干，其实进程早死了。船主完全分不清"在跑"和"进程被杀"。这正是挂账 daemon 丢活的无声版。
- **压到哪条圣域/宗旨**: 圣域⑫场所自留痕（中途散场也留）；三律之"坏得有声音"；活人感（假装还在思考）
- **崩了多严重**: P0（阻断/理念破产——假完成/假在跑，船主被静默欺骗）

- **压到哪条圣域/宗旨**: 记忆同一性（两场混进一个人的记忆）；场所忠实记录（行序错乱）；活人感（跨场鬼影发言）

- **崩了多严重**: P1（无声失败的变种：报了但报错对象，船主定位不到挂的是谁）

### 韧性混沌-05 · 事件 jsonl 撑到几百 KB，断线重连 replay 卡死
- **视角/人群/攻击向量**: 耐久 soak·无界增长（replay 全量重放）
- **前置状态**: 同一个 sid 被长期复用（前端把 sid 存 localStorage 反复用），`运行状态/会话事件/会xxx.jsonl` 已积到几百 KB（仓库里已真实存在 `stress-readonly-*.jsonl` = 388KB、`会01360b96c9.jsonl` = 53KB，佐证会长）。
- **操作步骤**: 用这个巨型 sid 打开一个新浏览器标签连 `/stream?sid=会xxx`。测：首帧多久到？前端打字机队列（一次一人匀速播放）要把几千条历史 delta 全播一遍吗？
- **健康的活公司应该**: replay 有上限（只补看最近 N 条或最近一场），首屏秒开，历史 delta 不逐字重播。
- **赌它会崩在**: `事件总线.py:46 _载入持久` 在 `_取会话` 冷启动时**把整个 jsonl 全读进内存 self.事件**，`SSE流`（143）replay 时**逐条 yield 全部历史事件**，包括成千上万条「在说 delta」逐字帧。前端打字机匀速播放队列会把**几个月的历史对话从头重播一遍**——星球回暖、思维流滚动，全是几周前的鬼影。断线重连不是"补看"，是"重活一遍"。而且 `self.事件` 内存无上限，长期只增不减。
- **压到哪条圣域/宗旨**: 体验（首屏/打字机）；活人感（历史被当实时重演，人格错乱）
- **崩了多严重**: P2（体验，但长期 soak 会拖成不可用）

- **前置状态**: PM 派活给工程师，白名单里给的是一个**目录**（如 `运行状态/` 或绝对 `/Users/.../运行状态`），干活人被要求在该目录下新建文件。
- **操作步骤**: 让 PM `assign_task` 的白名单传各种刁形态：`运行状态`（无尾斜杠）、`运行状态/`（有尾斜杠）、绝对路径带尾斜杠、模型实际 Write 时用**相对路径** `运行状态/x.md` 而非绝对。看 Write 是被执行还是被 PermissionEngine 静默 DENY。
- **健康的活公司应该**: 白名单语义稳定，模型无论写相对还是绝对、目录带不带尾斜杠都能命中；被拦时有明确"路径不在白名单"的可见理由。
- **赌它会崩在**: `活_本人.py:645-656` 干活白名单→写规则的拼装：`是目录 = _p.endswith("/")` 判断**依赖调用方是否带尾斜杠**；注释自己写着"⚠️ Path 拼接会吃掉尾 / …= 6 次派活失败的真根因"。若 PM 传的白名单**没带尾斜杠**（模型很容易不带），`是目录=False` → 规则变成**精确路径匹配**该目录本身，`file_path=运行状态/x.md` 的 glob **匹不上** → Write 被 fnmatch DENY。而 DENY 在流式底盘下大概率表现为**工具静默不执行/返回 Waiting**（活_本人.py:695 注释：非流式会停在 Waiting），船主在现场卡只看到"动作开始"没有"动作完成"，**活假装干了实则一个字没写**，最后 report 却可能自称写好了。旧根因换个入口复活。
- **压到哪条圣域/宗旨**: "坏得有声音"（写被拦却无明确报错）；活人感（自称干了实则没干=造假）
- **崩了多严重**: P1（假完成——报告说写了，文件没写，验收看文件列表才可能露馅）

### 韧性混沌-11 · SSE 慢消费 / 队列爆满，丢事件挂账现形
- **视角/人群/攻击向量**: 混沌工程·SSE 背压（队列满静默丢事件挂账 P1）
- **前置状态**: 一场大活，PM 开会/派活嵌套，短时间内爆发上千条 delta 事件（思考流+在说逐字）。前端故意慢消费（网络限速 / 标签页后台节流），或干脆挂着一个不读的 `/stream` 连接。
- **操作步骤**: 一边跑大活猛产事件，一边让某个订阅端**不 get**（模拟卡死的浏览器标签）。观察该队列的行为，以及别的正常订阅端会不会跟着丢。
- **健康的活公司应该**: 单个慢消费者不拖垮全局；即便丢事件，也要让该连接知道"你落后了、请重连 replay"。
- **赌它会崩在**: `事件总线.py:128 订阅` 队列 `maxsize=1000`，`发布事件`（113）用 `put_nowait` + `except: pass`——**队列满就静默丢**。慢消费的标签页队列一满，后续所有事件对它无声丢弃，且**没有任何"你落后了"的信号**；它界面停在某一刻，看起来像"公司不动了"，其实事件在别处照发。更糟：`持久 jsonl` 是全的、内存 replay 也是全的，但 **live 队列丢的那些**对已连接的慢端永久缺失（除非它主动断线重连走 replay，但它不知道自己该重连）。这是挂账"事件总线静默丢事件"的直接现形——丢了，无声。
- **压到哪条圣域/宗旨**: "坏得有声音"（队列满静默丢）；三律之"送达归平台"（平台没兜住送达）
- **崩了多严重**: P1（无声丢事件，慢端看到的公司状态与真实脱节且不自知）
