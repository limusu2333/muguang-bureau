## 一、relaychat —— 多人格连锁回复（谁接下一句）

**解决什么问题**：一个 AstrBot 挂多个 bot 人格，用户说一句后，人格们像真群友一样一个接一个"接话"，而不是各自孤立地回复用户。

### 核心机制（main.py + utils/decision_utils.py）

**1. 连锁的发动点是"发送后钩子"，不是收消息时**
`@filter.after_message_sent` → `_after_my_reply_sent()`：某个人格的回复真正发出去之后，遍历 `managed_bot_configs` 里**所有其他平台实例**，给每个安排一次连锁尝试 `_schedule_internal_chain_trigger()`。

**2. 排除上一发言者（两道闸）**
- 调度时：`if target_persona_name == replied_persona_name: continue`（不给自己安排连锁）；
- 处理时：`am_i_qualified = (not is_chain_event) or (current_persona_name != last_replier_persona)`——连锁事件里若"我"就是上一个发言的人格，直接弃权。
- 注意：它只排除**上一个**发言者，A→B→A 的回环是允许的（靠深度和概率截断）。

**3. 连锁靠"伪造事件重新入队"实现**
`_schedule_internal_chain_trigger()` 手工构造一个 `AstrBotMessage`：sender 设为刚发言的 bot（`Bot_{persona}`），raw_message 里埋六个私货字段：`__relay_is_chain__=True`、`__relay_depth__`、`__relay_last_replier_persona__`、`__relay_last_replier_physical_id__`、`__relay_original_user_mid__`、`__relay_original_user_sender_id__`，然后 `event_queue.put(simulated_event)` 塞回主事件队列——让下一个人格把"上一个 bot 的发言"当成一条普通来消息处理。**整个连锁状态机不靠全局变量，全靠随事件携带的元数据**，这是它最干净的一笔。

**4. 深度与概率截断**
- `max_chain_depth` 默认 1（`DEFAULT_MAX_INTERNAL_CHAIN_DEPTH=1`），每次连锁 `next_chain_depth = current+1`，达到上限不再调度；
- `chain_reply_probability` 默认 0.75（`DEFAULT_GLOBAL_CHAIN_REPLY_PROBABILITY`），连锁事件到达时 `random.random() < chain_prob` 才真的接话，所以链条是**概率衰减**的，不是必然走满深度。

**5. 随机延迟模拟人的节奏**
- 首次回复延迟：`initial_reply_min/max_delay_seconds` 默认 0.1–0.8s；
- 连锁间延迟：`chain_reply_min/max_delay_seconds` 默认 1.0–3.0s，`asyncio.sleep(random.uniform(...))`。

**6. 决策优先级链（DecisionModule.should_reply，六层从上到下）**
① 黑名单关键词（仅对非连锁、非自家bot的消息查）→ 拒
② 私聊 + 非连锁 → 强制回复
③ 连锁事件 → 只掷 `chain_reply_probability`，掷完就返回
④ 关键词命中 → 回复
⑤ **对话激励**：bot 刚回复过的会话，激励期内（默认 120s，`conversation_incentive_duration_seconds`）以 0.90 概率（`conversation_incentive_probability`）继续积极接话——实现是 `_active_conversation_sessions[session_key] = time.time() + duration` 一张过期时间表
⑥ 基础概率 `base_reply_probability` 默认 0.1 兜底

**7. 打断机制**：新用户消息到来时，按 `original_user_mid` 前缀取消所有还没跑完的旧连锁任务（`active_chain_tasks` + `chain_scheduler_lock`）——**用户插话，bot 们的排练作废重来**。

### 可搬进我们的"顺序群聊"
- "伪造事件重入队 + 事件携带链条元数据"的模式 → 我们的常驻智能体群聊里，"下一个说话的人"就应该收到一条带 `是连锁/深度/上一个发言者` 元数据的普通消息，调度器不用维护复杂状态机。
- 对话激励表（回过话的会话 120 秒内接话概率拉到 0.9）是让"话题热度"落地的最便宜写法。
- 新消息取消未执行连锁 → 船主一插话，排队中的 AI 发言全部作废，这条必须抄。

## 二、multi_bot_control —— 多 bot 共存限流（别让 AI 们把群刷爆）

**解决什么问题**：同一 QQ 群里多个机器人互相 @、互相唤醒、无限循环调 LLM。它不主动唤醒任何 bot，只在"本来就会被唤醒"时做限流、排队和提示词注入。

### 核心机制（main.py，单文件 1193 行）

**1. 状态粒度**：`BotSessionState`（turns / cooldown_until / last_accepted_at / recent_messages deque(32)），session key = `平台:群 : 我的身份 : 对端bot身份`——**每一对 bot 单独记账**，A-B 触发冷却不影响 A-C。LRU 上限 `MAX_SESSION_STATES=2048`。

**2. 六重闸门（`_can_accept_bot_request()`，按序判断，任一不过就 `event.stop_event()` 静默拦截）**
| 闸门 | 参数（schema 默认值） |
|---|---|
| 对端允许交互 | `allow_interaction=True` |
| 单对会话连续轮次上限 | `max_turns_per_session=2`，超限进冷却 `cooldown_seconds=60` |
| 同一对端最小间隔 | `min_interval_per_peer_seconds=5` |
| 群窗口总量 | `group_window_seconds=150` 内最多 `max_bot_replies_per_group_window=6` 条 bot 回 bot |
| **无人类介入限制** | `without_human_window_seconds=150` 内无人类时最多 `max_bot_replies_without_human=10` 条，超了全群冷却 `without_human_cooldown_seconds=90` |
| 重复消息过滤 | `_stable_message_hash`（空白归一+casefold+sha256），`duplicate_window_seconds=60` 内同 hash 最多 `max_same_message_per_session=5` 次 |

**3. 人类发言 = 复位键**：`_record_human_activity()`——检测到非 bot 名单的发言者，清空该群"无人类"计时窗，并把未在冷却中的会话 turns 归零。**人类一说话，AI 们的配额恢复；人类不在场，AI 们聊几句就必须闭嘴**。这是"防止两个 AI 深夜互刷一万条"的关键。

**4. 只在实际发出后记账**：限流预登记放在 `event.set_extra(PENDING_REPLY_EXTRA, ...)`，`@after_message_sent` 里确认 `_has_send_oper` 才 `_commit_bot_reply()` 累加轮次——LLM 调了但没发出去不消耗配额，避免误扣。

**5. 同时被 @ 时的排队**：`_self_rank_delay()`——多个受控 bot 同时被点名时，每个 bot 按 `_stable_priority()`（对 `插件名:身份` 做 sha256 取前 8 字节 mod 1,000,000，**无需通信就有全局稳定的一致排序**）排序，第 rank 名延迟 `rank * controlled_reply_spacing_seconds`（默认2s）再回。另有基础延迟 `bot_request_delay_seconds=2`。

**6. 给 LLM 注入"对面是 AI"**：`inject_bot_prompt()`（on_llm_request 钩子）把模板注入（优先 `extra_user_content_parts` 临时消息、失败回退拼 system_prompt）。默认模板原文要点：
```
<bot_interaction> 当前消息来自另一个机器人，不是普通用户。对方昵称…你必须称呼对方为…</bot_interaction>
<bot_reply_style> 不要主动反问，除非人类用户明确要求讨论。不要主动呼叫其他机器人。
不要 @全体成员。不要模拟其他机器人的身份。</bot_reply_style>
```
"不要反问、不要呼叫其他机器人"这两条是从提示词层面掐断无限循环的第二保险。

### 可搬进我们的"常识门"
- **"无人类介入配额 + 人类发言复位"整套逻辑直接搬**——小酒和其他智能体互聊时，船主不在场就限每窗口 N 条，船主一开口即恢复，这就是常识门里"别自嗨"的机械化版本。
- 重复消息 hash 过滤（归一化+sha256）防复读，几行代码的事。
- "只在实际发出后记账"的 pending→commit 两段式，配额系统都该这么写。
- 哈希稳定优先级：多智能体同时想说话时不用中心调度也能排出一致顺序。

## 三、Heartflow —— 心流插件（小模型守门 + 精力系统）

**解决什么问题**：bot 只在被 @ 时才说话太死板，每条都回又太吵。用一个便宜小模型给每条群消息打分，过阈值才唤醒大模型"主动"参与，且用"精力"防话痨。

### 核心机制（main.py，单文件 829 行）

**1. 五维打分（README 说四维，代码实际五维）**
`judge_with_tiny_model()` 让小模型对每条消息输出 JSON 五个 0-10 分：
- `relevance` 内容相关度（权重 `judge_relevance=0.25`）
- `willingness` 回复意愿（0.2）——prompt 里喂了当前精力值
- `social` 社交适宜性（0.2）
- `timing` 时机恰当性（0.15）
- `continuity` 对话连贯性（0.2）——当前消息是否在接 bot 上一句的话茬，无记录给默认 5 分
综合分 = Σ(分×权重)/10，≥ `reply_threshold`（默认 **0.6**）才回。权重和≠1 时自动归一化。判定通过后只做一件事：`event.is_at_or_wake_command = True`，**伪装成被唤醒，让主系统正常走大模型流程**——判断与生成彻底解耦。

**2. 精力系统（ChatState，按群独立）**
- 初始 `energy=1.0`；
- 回复一次扣 `energy_decay_rate=0.1`（下限 0.1）；
- 不回复每条消息回 `energy_recovery_rate=0.02`；
- 按时间流逝恢复：距上次回复每 5 分钟回 1%（`elapsed_minutes * rate*5`，实现在 `_get_chat_state`）；
- 每日首查加 0.2。
精力本身**不硬性禁言**，而是作为数字写进小模型 prompt（"我的精力水平: x/1.0"），让模型自己在 willingness 维度体现疲惫——软约束，很妙。

**3. 成本控制三件套**
- 人格提示词压缩：`_summarize_system_prompt()` 用小模型把大人格设定压到 100-200 字，按 `persona_id` 缓存（`system_prompt_cache`），判断时用压缩版；
- 自建原始消息缓冲 `_raw_msg_buffer`（deque，容量=max(context,judge)×4）：记录**所有**群消息而非只有触发过 LLM 的，判断上下文来自这里（`context_messages_count=5`）；
- JSON 解析三段式 `_extract_json()`：直接 parse → 剥 markdown 围栏 → 正则抠 `{...}`，失败重试 `judge_max_retries=3` 次且每次在 prompt 里加压。

**4. 回复效果自察**：`_build_chat_context()` 看 bot 上次发言后有没有人接话——≥3 条 →"上次回复后群里进行了热烈讨论"，0 条 →"上次回复后无人接话"，写进下次判断 prompt，形成粗粒度反馈闭环。

**5. 注入自知**：心流触发的回复在 `on_llm_request` 里给大模型加一句"本次是你主动参与群聊的，不是用户叫你。回复应自然随意，像普通群成员一样加入话题。"

### 可搬进我们的"常识门"
- **五维打分表几乎就是常识门的现成评分卡**，本地小模型（Gemma 级）完全跑得动；continuity 维度（在不在接自己的话茬）对"小酒该不该接话"尤其关键。
- 精力值作为 prompt 数字软约束而非硬开关——比"冷却时间到就闭嘴"更像人。
- "上次发言后无人接话"回灌下次判断，是最便宜的效果反馈。

## 四、MaiBot —— 表达学习 / 黑话学习 / 回复效果 / 发言节奏

**解决什么问题**：让 bot 越聊越像"这个群的人"——学群友的说话风格、学群黑话，并且事后度量自己每句话的效果，控制自己在多个群之间的注意力节奏。

### 4.1 表达学习（learners/expression_learner.py）

**学什么**：从群聊里抽 `(situation 情景, style 风格)` 对，如"表示惊讶→卧槽还能这样"。回复时按当前情景检索匹配的 style 用进去。

**流水线**：
1. 素材：只取真实聊天消息（`source_kind ∈ {user, guided_reply, outbound_send}`），至少 `min_messages_for_extraction=10` 条才开一批；
2. 并发闸门 `ExpressionLearningBatchGate`：同会话互斥 + 全局上限 `max_expression_learner`；
3. 多 message 构造：每条消息独立 user message，带 `[source_id:N] [speaker:USER/SELF] [name] [time]`，system 里明说"**speaker=SELF 的消息只作上下文，不要从 SELF 的发言中学习**"（防止风格近亲繁殖，自己学自己会越学越窄）；temperature=0.3；
4. `_filter_expressions()` 硬过滤：source_id 必须能对上原始行且那行**不是 bot 自己发的**；剔除含 SELF / [表情包 / [图片 / 与 bot 名字重名的 style；单批超 20 条判为幻觉整批丢弃；
5. 入库 `_upsert_expression_to_db`：完全一致（style 相同 + situation 完全匹配）→ `count+1` 并把新 situation 追加进 `content_list`；多个 situation 会由 LLM 概括成"不超过 20 字"的一句（`_compose_situation_text`，只取最近 10 条）；否则新建 count=1；
6. 可选 AI 自审（`expression_self_reflect`）+ 向量索引重聚类（`vector`/`vector_intent` 检索模式）。

### 4.2 黑话学习（learners/jargon_learner.py + jargon_miner.py）

**学什么**：群内特有词汇/梗（"黑话"），存词条+证据+推断含义，之后遇到时能看懂并正确使用。

**入库（jargon_learner）**：LLM 从带 source_id 的上下文里抽黑话候选 → 过滤（含 SELF / 含 bot 昵称 / source_id 非法的丢弃）→ 取候选所在行**前3后4共至多7条**做证据上下文，并把真实消息的 `(platform, message_id)` 存成 `evidence_messages` 引用（不存文本存指针，推断时再从库里还原，消息删了自动剔除证据组）→ `JargonMiner.process_extracted_entries()` 合并写库：已有记录 `count+1` 并合并证据；新词 count=1。另有 LRU 缓存 50 条（`cache_limit`）：库里已有的黑话在新消息里再出现时正则直接命中回填，不用等 LLM 再抽一次。

**含义推断（jargon_miner，最精的部分）**：`JARGON_INFERENCE_THRESHOLDS = [4, 8, 25, 100]`——词条出现第 4/8/25/100 次时各触发一轮推断（`last_inference_count` 防重复），count≥100 后 `is_complete` 封笔。每轮**三段式**：
1. `jargon_inference_with_context`：带证据上下文推含义（可参考上次含义迭代更新）；
2. `jargon_inference_content_only`：**只给词、不给上下文**再推一次；
3. `jargon_compare_inference`：比较两个结果——**相似 → 这词的意思人尽皆知，不是黑话；有差异 → 上下文赋予了它特殊含义，是真黑话**（`is_jargon = not is_similar`）。
这个"对照组"设计干净利落地解决了"什么才算黑话"的定义问题。手动录入的词条（`created_by=MANUAL`）永远不被 AI 覆盖。

### 4.3 回复效果追踪（reply_effect/，"说完之后学没学到"）

每条 reply 发出后开一条 `ReplyEffectRecord`，观察窗 `OBSERVATION_WINDOW_SECONDS=600`（10分钟），收集后续消息快照。提前结算条件（tracker._resolve_finalize_reason）：目标用户明确负反馈 / 修复循环（"我是说""你理解错"等词命中）/ 目标用户 2 条 followup（`TARGET_USER_FOLLOWUP_LIMIT=2`）/ 全会话 5 条（`SESSION_FOLLOWUP_LIMIT=5`）/ 超时。

结算打 **ASI 分（0-100）** = `0.45×行为分 + 0.35×感知分 + 0.20×(1-摩擦分)`（scoring.py）：
- 行为分（纯规则、零成本）：对话是否延续≥2轮(0.30) + 情绪估计(0.25，正/负/修复三张中文模式词表数命中) + 用户展开度(0.20，均长>8字起算) + 无纠正(0.15) + 无放弃(0.10，出现"算了"或两次负词判弃)；
- 感知分（LLM窄评审，judge.py）：social_presence(0.35)/warmth(0.25)/competence(0.25)/appropriateness(0.15)，1-5分制归一；**另有 uncanny_risk 维度专门量"过度拟人/油腻/越界"**，计入摩擦分(0.30权重)；
- 非目标用户的反馈只按 0.65 权重计（`source_weight`），并在 `confidence_note` 里注明置信度低。

### 4.4 发言节奏（focus/）

**FocusModeManager（manager.py）**：全局（或按 focus_groups 分组）只有 `FOCUS_SLOT_LIMIT=1` 个"专注席位"，只有坐在席位上的聊天才被允许跑决策主循环（`can_decide`）。`focus_cool_time` 默认 120s。关键防抖：`release_focus_and_block_next_entry()` 退出后把该聊天记为"下一轮禁入"，**防止刚退出的群立刻回抢席位**造成乒乓。

**runtime_mixin.py**：`FOCUS_NO_ACTION_EXIT_THRESHOLD=5`——连续 5 次决策循环空闲收尾（没说话没动作）自动退出专注，把注意力让给别的聊天；冷却定时器到点检查其他聊天有没有积压未读，有则唤醒切换。整体效果：**bot 同一时刻只"泡"在一个群里，聊淡了自动换地方**，而不是所有群同时高频轮询。

### 可搬进我们的"表达学习"
- (situation→style) 二元组 + 出现计数 + LLM 概括合并，是表达库的最小可行 schema，比存原句好检索得多；
- "**不学 SELF**"红线和防幻觉硬过滤清单（表情/图片标记、bot 名、source_id 回查）整套照抄；
- 黑话三段式"上下文推断 vs 裸词推断 vs 比较"+ 4/8/25/100 递进阈值 → 小酒学船主和群友的私房梗就用这套，证据存消息指针而非文本；
- ASI 里的 uncanny_risk（过度拟人风险）维度对数字小酒是**特别值得单列**的自察指标；
- focus 单席位 + 连续5次空闲退出 + 退出禁止回抢，就是"过日子的进程"在多个聊天间分配注意力的现成节奏器。

## 五、四个项目拼成一张图

```
一条群消息进来
   │
   ├─ Heartflow式常识门：小模型五维打分(带精力值/连贯性) ≥0.6 才醒  ←—"该不该说"
   │
```
