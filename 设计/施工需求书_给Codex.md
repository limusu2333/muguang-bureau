# 施工需求书 · 窗户换脸「深空全息」（给 Codex）

## 目标
把 `前端/` 的**视觉层整体重构**为「深空全息」定稿语言。功能一个不丢，脸整个换掉。

## 视觉真相（唯一标准，先在浏览器里打开看过再动工）
- `设计/光环_动态预览_母版.html` = 待命态
- `设计/开机_动态预览_母版.html` = 公司工作中态
- `设计/打板_动态预览_母版.html` = 待你拍板态
逐像素还原三张母版的视觉与动效；代码允许重组织为 React 组件，观感不允许偏离。
设计军规见 `设计/C_窗户设计定稿_深空全息.md`（无容器/色只上光/一个活物/呼吸红点/文案不嗲），每写一个组件对照一遍。

## 必须保留的功能（破坏任何一条=返工）
- `前端/src/api.ts`、`actions.ts`、`hallStore.ts` 的**数据逻辑与端点语义**：`/活厅`、`/stream`(SSE replay+live)、`/插话`、`/panic`、`/活厅_验收`、`/board`、`/hall`、`/room`、`/rollcall`。文件可以移动重命名，处理逻辑（乐观气泡、匀速打字机、活人单元事件流、暂停hall轮询）不得改语义。
- 大厅按天归档历史、点名流、附件发送、项目室（Room）功能保留——Room 本次只做暗色系适配（次优先，可朴素但不许刺眼白底）。

## 新视觉架构
1. `HaloCanvas` 组件：粒子光环状态机，三态参数照三张母版（idle 大而慢 / working 小而快+口令行 / verdict 远而暗）。母版里的 canvas 代码可直接移植。
2. 无框导航（悬浮字+琥珀刻线+呼吸红点，红点数据接 `待办.活公司待验收+待裁决` 数量>0）。
3. 引线标注层（SVG 线+端点，待命态两条标注；working 态三个 crew 悬浮位接**真实** `活人单元` 数据——名字/岗位/最新一句/元数据，状态点颜色: 干活=琥珀呼吸, 失败中=红）。
4. 指令行（无框底线式输入，待命="对公司下达指令"，工作中="插话"），行为接现有 `智能发送`。
5. 打板层（verdict）：待验收数据来自 `待办.活公司待验收`，批准/打回调现有 `活公司验收()`，批准瞬间全屏一帧白闪(60ms)。请示裁决同样式接 `决策()`。
6. 四角状态读数（SCENE=场次号可用会话计数或日期、实时时钟、MEM/CREW 接 board 数据）；角标、斜纹肌理、MUNAEA 描边水印，全按母版。

## 硬约束
- 只动 `前端/` 目录。`工具/*.py` 一个字节不许碰。
- 不引入任何新 npm 依赖（纯 canvas + CSS 已够）。
- 旧 `暗房亮桌.css` 保留文件但不再引用（历史资产）。
- 示例内容禁止硬编码进组件（母版里的"她的房间"等是演示假数据）；"主人"问候语可暂硬编码并标注 `// TODO 接配置`。
- `npx tsc --noEmit` 0 错；`npm run build` 通过。
- 分阶段 git commit（Conventional Commits，中文说明），**完工必须 commit**。
- `prefers-reduced-motion` 降级：环静帧+缓呼吸。
