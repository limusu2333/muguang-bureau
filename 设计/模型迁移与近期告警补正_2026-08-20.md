## 两个告警问题的根因

### 历史失败反复弹出

原来的健康汇总把“近 7 天失败数量”同时当成统计和当前告警。失败即使已经结束，重启后仍会再次要求船主处理。现在它只进入统计与历史；只有仍处于活动状态、确实需要决定的问题才生成问题卡。

### 中文补充提交失败

问题卡把补充内容转交给本机 `/活厅` 时，内部网址中直接带了中文路径。Python 的底层 HTTP 客户端只能用 ASCII 编码网址，因此在发出请求前就报错，正文根本没有到公司。现在只对内部网址做标准 URL 编码，中文正文继续使用 UTF-8 原样传递；接收端解码后仍识别为 `/活厅`。

## 明确未改的部分

意图判定门当前仍由 `工具/活_本人.py` 的 `_判定门岗位` 指向文案工程师岗位，也就是当前的 `deepseek-v4-pro-0813`。本轮只把错误的旧注释改成真实现状，没有调整判定逻辑、超时、提示词或模型。实例主人将另行讨论这一层，后续不能把本次维护误写成“意图门已重设”。

## 验收口径

- 自动回归必须覆盖：Token Plan 共用密钥时的模型家族识别、历史失败不生成当前警告、中文补充能到达内部活厅且正文不变。
- `make check` 必须全部通过，并完成前端生产构建。
- 正式办公室重启后，`/健康` 必须返回 0 错误、0 警告，五个岗位的具体模型都要收到真实回复。
- 最终提交后复核 Git 工作区；未跟踪的运行日志、密钥和备份不得进入提交。
