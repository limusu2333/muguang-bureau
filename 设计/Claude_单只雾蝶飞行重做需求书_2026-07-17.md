## 一、你先理解这次为什么重做

前面多轮失败始终是同一个问题：

- 翅膀在播放动画，身体却沿路径匀速漂移，两者没有真实因果关系。
- 蝴蝶常常横着平移，头部并不稳定地朝向飞行方向。
- 拍翼时没有对应的上升、加速和姿态变化；停止拍翼后也没有明显受重力下沉。
- 所谓三维只是模型有厚度，运动逻辑仍是二维贴图平移。
- 转弯像新手赛车甩头，拍翼像合页或扑棱蛾子，不优雅、不像影视级生物。
- 反复调整路径、速度、CSS 或外观不能解决根因。根因是飞行动力、骨骼动作、身体姿态和路径控制没有成为同一个系统。

这次禁止再用“看起来差不多”验收。要用真实运行画面和运动数据共同证明。

## 六、飞行必须符合的物理语义

这里不要求做科研级空气流体求解，但必须保住真实飞行的因果关系。

### 1. 世界方向

- 屏幕下方就是地面方向。
- 世界重力始终向下，不能随路径旋转。
- 空气可以提供阻力和升力，但不能让蝴蝶无动力永远悬空。

### 2. 拍翼必须驱动身体

- 每次可见的下拍必须产生一次对应的升力脉冲和向头部前方的推进脉冲。
- 身体速度和高度要在拍翼后发生可测变化，不能只改翅膀骨骼时间。
- 翅膀不拍时，不能继续获得同等推进力。
- 翅膀动画相位必须是动力计算的同一个相位源，不能动画一套钟、运动另一套钟。

### 3. 滑翔必须受重力

- 展翼滑翔时可以因为速度获得部分升力，下降变慢。
- 但净结果仍应逐渐减速、下沉；高度不足或速度过低时，蝴蝶才重新拍翼补能量。
- 飞行节奏应是“几次有力拍翼 → 安静滑翔 → 必要时再次拍翼”，不是持续高频扑腾。

### 4. 头、身体和速度必须一致

- 头部稳定朝向实际速度方向，不是朝路径点瞬间甩动。
- 上升时身体自然抬头，下降时自然俯冲。
- 转弯时先平滑改变方向并产生侧倾，不能瞬间翻转。
- 侧倾、俯仰和转向必须有限速和阻尼。阻尼就是“不会突然抽动，而是逐渐转过去”。

### 5. 路径只是意图，不是传送带

- 可以有循环路线，但路线只能提供“想往哪里飞”的目标。
- 位置必须由速度和受力积分得到，禁止 `position = curve.getPointAt(time)` 这种按时间直接摆位置。
- 路径进度必须由真实位移或真实速度推进；蝴蝶减速时，路径进度也必须减慢。
- 路线按用户草图：从低处开始拍翼爬升，经过上方长滑翔，在右侧转弯下降，再从低处回到下一轮。

## 七、翅膀形变和美感

- 继续使用现有骨骼动画中的翅膀、腹部、触角和胸部联动。
- 翅膀不能像两块硬纸板绕合页转。检查骨骼动画是否已经包含弯曲；不足时，可以在不破坏模型的前提下增加轻微的骨骼延迟、翼尖滞后或顶点形变。
- 翼根先受力、翼尖稍后跟随；回收时也要有轻微滞后，形成柔软感。
- 不能靠夸张残影掩盖动作。默认关闭强残影和拖尾。
- 保持雾中醒来的珍珠、薄膜、半透明和冷暖微虹彩，不做水墨国风，不加粗边框。
- 飞行要优雅：频率低一些、动作有停顿、滑翔占明显时间、转弯有准备和收势。

## 八、单只原型的状态

本次只需要验证两种状态，但必须区分清楚：

- **待机巡游**：低频、有力的两到三次拍翼，随后较长滑翔；路线宽、速度舒缓。
- **思考中**：拍翼频率和响应略提高，身体更清晰、靠近一点，并有克制的呼吸光；不能变成焦躁扑腾。

状态切换不能重置位置、瞬移或突然变速。旧主题切走后必须停止本主题的动画帧和 Three.js 渲染；切回来再恢复，不能两套主题同时在后台跑。

## 十、性能和资源生命周期

- Three.js 画布按实际显示尺寸和设备像素比渲染，像素比设合理上限，不能无限吃显卡。
- 页面不可见、窗口失焦、`prefers-reduced-motion` 或主题切走时，停止或显著降频。
- 卸载时取消 `requestAnimationFrame`，释放 geometry、material、texture、mixer 和 WebGL context。
- 目标是普通 Mac 浏览器稳定接近 60fps；如果达不到，先查每帧分配、材质透明排序、像素比和重复查询，不许直接删掉关键飞行效果。

## 十一、必须做的验收

### A. 运行画面

1. 单独打开原型，连续观看至少 30 秒。
2. 至少看完两轮“拍翼 → 上升/加速 → 滑翔 → 下沉/减速 → 转弯”。
3. 用不同时刻的连续截图或录屏核对，而不是只挑一张最好看的静帧。
4. 桌面宽屏和较窄窗口各看一次，蝴蝶不能飞出可视区后长期不回来。

### B. 运动记录

开发模式记录每帧或每隔几帧的：

- 时间；
- 当前状态；
- 三维位置与速度；
- 翅膀相位；
- 下拍力度；
- 垂直加速度；
- 身体前向、俯仰和侧倾。

必须证明：

- 下拍之后约 150 毫秒内，垂直速度总体向上变化；不能毫无关系。
- 滑翔阶段平均垂直加速度向下，高度会下降。
- 速度有清楚的快慢变化，不是几乎恒定，也不是失控乱冲。
- 身体前向和实际速度方向的中位误差小于约 12°，绝大多数时刻小于 35°。
- 画面路线至少覆盖约 35% 宽度和 25% 高度，肉眼能看出完整飞行，而不是原地挣扎。
- 没有瞬移；单帧位移不能突然远大于相邻帧。

这些数字不是让你调参骗过测试，而是防止再次把“会动”误报成“会飞”。

### C. 工程检查

- `npm run typecheck` 通过。
- `npm run build` 通过。
- 浏览器控制台 0 错误；模型加载失败必须在页面或控制台明确报错，不能静默空白。
- 检查主题切换后旧主题的动画帧确实停止。
- 检查点击区域跟随蝴蝶。
